# Upstream `release/v1.3.0` triage

Assessment of `upstream/release/v1.3.0` (lumoe/obsidian-rollover-daily-todos) against this fork's `main`, written 2026-10-20 as a read-only review of the diffs. The [Outcome](#outcome) section records what was adopted afterwards; the sections below it are the original assessment.

## Summary

The branch is 27 commits ahead of `upstream/master`. Most of the ~8.4k added lines are the lockfile and e2e specs. The behaviour changes live in five small modules, and the UI change is additive (one source-action dropdown, one marker field, about six toggles), so the logic can be taken without the UI.

`main` has already rewritten the rollover core (`getSections`, heading ancestry, `removeEmptyHeadings`, its own `insertUnderHeading`). Commits touching `index.js` will conflict heavily, so port ideas and the pure modules rather than whole commits.

## Outcome

Adopted over five steps plus follow-ups, as a stack of branches (`main` → `feat/parser-options` → `feat/mark-as-moved` → `feat/skip-existing-todos` → `feat/templater-safeguard` → `feat/settings-tab-resilience` → `fix/followups`). Each change is ported by hand and adapted to the fork's section-aware rollover rather than cherry-picked, because upstream's `index.js` rewrite conflicts with it. Commit ids are those on the branches.

| Step | Commit | What was adopted | How it differs from upstream |
| ---- | ------ | ---------------- | ---------------------------- |
| 1 | `48171bc` | Anchored todo regex, `ignoreBlockquotes`, `skipCompletedChildren` | With delete-on-complete, skipped completed children are removed from the previous note together with their rolled parent (by line position), so they are not orphaned. `getSections` forwards the options. |
| 2 | `1e0cace` | Mark-as-moved: `onRolloverSourceAction` = `none` / `delete` / `mark`, with a marker character | Only open todos are marked (completed children keep `[x]`). The marker counts as a done marker while marking, without changing the saved `doneStatusMarkers`. `deleteOnComplete: true` migrates to `delete`. Delete logic moved unchanged into a tested pure function. |
| 3 | `403e87f` | Skip todos already in today's note; newline fixes when inserting | Duplicates are grouped with their children, compared against the note before insertion, and still count as handled for mark/delete. Skip-horizontal-rule and append-below-existing-tasks were not needed (see below). |
| 4 | `c7ef430` | Templater safeguard | Only waits (3 s) when Templater is enabled and the action is mark or delete, and checks that the final state still contains the rolled todos instead of listening for any foreign write. |
| 5 | `215204e` | Settings page no longer goes blank; free-text heading fallback | `rollover()` also guards against unreadable settings. A saved heading missing from the template stays in the dropdown. |
| follow-up | `d714e06` | Refreshed `pnpm-lock.yaml` | The lockfile was stale, so a frozen install (the CI default) failed. |
| follow-up | `de4d7b4` | Missing-heading notice now appears | The existing check could never be true. |
| follow-up | `5119ce4` | With Templater enabled, undo restores only the previous day's note | Today's snapshot would have been the unrendered template. `UndoModal` handles a missing snapshot. |

### Not adopted

| Change | Reason |
| ------ | ------ |
| Section routing | The fork's version creates missing headings and keeps full heading ancestry. |
| Skip `---` after the heading | The fork inserts at the end of the heading's section, so todos already land below a rule. |
| Append below existing tasks | Same: the fork already appends at the end of the section. Placement directly after the list, ahead of other text in the section, was declined. |
| Inlined `daily-notes.js` | The only gain is Periodic Notes 1.0 support. The maintainer does not use Periodic Notes, and the plugin has not been updated in about five years. `obsidian-daily-notes-interface` stays. |
| Persisted undo across restart | Stores note contents in `data.json`; judged not worth it. Not implemented. |
| wdio e2e infrastructure, `latest` dev dependencies, `manifest.json` / `package.json` changes | Heavy for a personal fork; `minAppVersion` and versioning stay the fork's own. |

### Known gaps

- Nothing here has been run inside Obsidian. The pure logic is unit tested; the settings tab, the Templater wait and the delete/mark flow in `rollover()` are only built and reviewed.
- The Templater check cannot catch a template slower than 3 seconds, and only Templater is detected.
- Skip-existing compares against the note as Obsidian first created it, so a recurring task generated by rendering a Templater tag is not recognised as a duplicate.
- Delete and mark act on line positions found when the previous day's note was parsed. If that note is edited while the rollover runs (for example during the Templater wait), it is left unchanged and a notice says so. Today's note already has the rolled todos at that point, so running "Rollover Todos Now" again inserts them a second time unless skip-existing (**#10**) is on.

### Risks in upstream's code

1. **CRLF files.** `insertUnderHeading` splits on `"\n"` and matches the heading with strict equality. On CRLF the heading keeps a trailing `\r`, the match fails, and todos silently go to the end of the file. The old `String.replace` did not have this problem.
2. **Default behaviour changes.** `skipHorizontalRule` defaults to true, changing placement for anyone with `---` under their heading. The `deleteOnComplete` to `onRolloverSourceAction` migration is one-way.
3. **Delete by line equality.** The source action removes every line identical to a rolled todo, including duplicates elsewhere in the note. "Mark" would inherit this. Resolved in the port: delete and mark use line positions (fork issue #4 on hoshposh/obsidian-rollover-daily-todos).
4. **Settle window.** The modify listener can still miss a clobber landing after 3 s, and it adds up to 3 s latency.

### Suggested order

1. Parser options: anchored regex, `ignoreBlockquotes`, `skipCompletedChildren`, with tests. These cherry-pick cleanly.
2. Mark-as-moved, using the pure module.
3. Skip-existing and the template placement options.
4. A simplified Templater safeguard.
5. Settings-tab resilience fix, whenever convenient.
