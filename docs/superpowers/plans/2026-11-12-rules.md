# Rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rule list in a new Rules settings section. Each rule matches a todo by tag, heading or regex and sets its default outcome, marks it as not a todo, exempts it from the stale counter, or moves it to another heading in today's note.

**Architecture:** A new pure module, `src/rules.js`, does all matching and holds the example rules and the settings-facing text helpers. The parser takes an `isIgnored` predicate for "Not a todo". `planDecisions()` attaches a rule result to each item, and the existing steps read it: `defaultDecisions()`, `isStale()`, `applyDecisions()` (moved sections), `planInsert()` (no counter bump) and `insertSections()` (moved sections). The UI (settings group, rule dialog, review labels) only renders what `rules.js` returns.

**Tech Stack:** Plain JavaScript ES modules, Obsidian `Modal`/`Setting`/`PluginSettingTab` API, rollup, vitest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-12-rules-design.md`

## Global Constraints

- With no rule switched on, every path through `rollover()` produces exactly what it does today. Existing tests pass unchanged, except `settings-text.test.js`'s group list, which gains "Rules".
- Example rules are seeded only when stored settings have no `rules` key, all with `enabled: false`, and never reseeded.
- A rule never throws during a rollover. A rule with a problem (`ruleProblem()` non-empty), a disabled rule, or a malformed object from a hand-edited `data.json` never matches.
- Rule effects, internal → shown: `roll` Roll, `backlog` Backlog, `cancel` Cancel, `leave` Leave, `ignore` Not a todo, `noStale` No stale count, `move` Move to heading. Match types: `tag` Tag, `heading` Heading, `regex` Regex.
- Within a kind (outcome / noStale / move) the first matching enabled rule wins. Kinds combine. `ignore` acts in the parser and outranks everything.
- An unavailable outcome (Backlog with no backlog note, Cancel when `isCancelAvailable()` is false) leaves the outcome to the normal default. The next outcome rule does **not** take over.
- Move to heading ignores `templateHeading`. The target is searched in the whole of today's note (by text, ignoring level and case, first match), and is appended at the end when missing.
- DOM via `createEl`/`createDiv`/`createSpan`/`setText` only, never `innerHTML`. Theme CSS variables only, usable at phone width. CSS only in `styles.css`.
- Changing the rule list re-renders only the Rules group's container, never the whole tab.
- Commit messages: plain imperative subject, no `Co-Authored-By` or `Claude-Session` lines (the user's global CLAUDE.md).
- Run prettier only on files a task creates, never repo-wide.
- Tests: `pnpm vitest run <file>` or `pnpm vitest run`. `pnpm build` must exit 0 after any task that touches `src/index.js`, `src/ui/` or `styles.css`.

## Review Focus

1. **Settings saved by 1.3.x (no `rules` key):** the examples are seeded switched off, and a rollover is identical to one with no rules. Tests: Task 1 (`EXAMPLE_RULES` all disabled, no result for a `#someday` todo), Task 4 (flow with `EXAMPLE_RULES` equals flow with `[]`).
2. **A hand-edited or partial rule** (missing `match`, `value: 42`, unknown effect, `null` in the array): ignored, never throws. Test in Task 1.
3. **Tags that only look like the rule's tag:** `#somedayish`, `#someday` inside inline code, `#Someday` (matches), `#someday/later` (matches), `foo#someday` (no match). Test in Task 1.
4. **A todo that is No stale count and already over the threshold** with `staleBehavior: "backlog"`: defaults to Roll, shows no badge, does not open a "stale" review, and its counter does not rise. Tests in Task 3 and Task 4.
5. **A move target that today's note has at another level, or twice:** the first heading with that text is used, whatever its level. Test in Task 4.

**Interfaces:**
- Consumes: `TAG_END` (string, regex character class) from `get-todos.js`; `LIST_PREFIX` from `rollover-items.js`; `normalizeHeading(text) → string` from `backlog.js` (`"Inbox"` → `"## Inbox"`, `"### X"` unchanged).
- Produces:
  - `MATCH_TYPES = ["tag", "heading", "regex"]`, `EFFECTS = ["roll", "backlog", "cancel", "leave", "ignore", "noStale", "move"]`, `OUTCOME_EFFECTS = ["roll", "backlog", "cancel", "leave"]`.
  - `EXAMPLE_RULES`: the nine rows of the spec's **Example rules** table, in that order, each `{ id, enabled: false, match, value, effect }` plus `target: "## Inbox"` on the Move row. Ids are fixed strings `"example-1"` … `"example-9"`.
  - `ruleProblem(rule) → string`: `""` when usable. Otherwise exactly: `"Unknown rule."` (not an object, or unknown `match`/`effect`), `"Enter a tag."` / `"Enter a heading."` / `"Enter a pattern."` (value missing, not a string, or blank), `` `This pattern is invalid: ${error.message}` `` (regex that does not compile with the `u` flag), `"Enter the heading to move to."` (move with blank `target`).
  - `ruleMatches(rule, headLine, headingPath) → boolean`: false when `!rule?.enabled` or `ruleProblem(rule)`.
  - `isIgnoredByRules(line, headingPath, rules) → boolean`: some enabled `ignore` rule matches.
  - `ruleResult(headLine, headingPath, rules, { backlogEnabled, cancelEnabled }) → { outcome, outcomeRule, noStale, noStaleRule, moveTo, moveRule }`. `outcome`/`moveTo` are `null` and the `*Rule` fields `null` when nothing applies. `moveTo` is `normalizeHeading(rule.target)`. An unavailable outcome gives `outcome: null, outcomeRule: null`, and scanning for the outcome kind stops there.

Matching, per the spec's **Matching** section:
- **Tag:** the value is trimmed. A value starting with `@` is used as is; otherwise one leading `#` is stripped and `#` added. Tested with `new RegExp(`(?:^|\\s)${escaped}(?=$|/|${TAG_END})`, "iu")` against the line with inline code removed (the same replace `hasRolledMarker()` does).
- **Heading:** compare `strip(value)` with `strip(h)` for each `h` of `headingPath`, where `strip` removes leading `#`s and spaces, then trims and lowercases.
- **Regex:** `new RegExp(value, "u")` tested against `headLine.replace(LIST_PREFIX, "").trim()`. Compile once per rule per call; caching is optional.
