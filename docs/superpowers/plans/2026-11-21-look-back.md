# Look Back Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a rollover also read the daily notes from the last N days (Look back), as extra sources, without ever bringing back a todo that was finished in a newer note.

**Architecture:** A pure window lookup in `src/daily-notes.js` and a new pure module `src/look-back.js` (when Look back applies, its start date, parsing its settings, and "done in a newer note"). `src/rollover-sources.js` gets a third source kind, `"earlier"`, with hidden and handled items, and `planInsert()` learns to drop handled items. `index.js` reads the older notes and wires it together; the review dialog and settings tab get small changes.

**Tech Stack:** JavaScript (ES modules, rollup to CommonJS), vitest, moment (tests; `window.moment` at runtime), the e2e harness in `e2e/`.

**Spec:** `docs/superpowers/specs/2026-11-21-look-back-design.md`

## Global Constraints

- With `lookBackDays` 0, missing, or its dependencies not met, a rollover reads and writes exactly what it does today: `e2e/baseline.e2e.js` and every existing e2e and unit test pass unchanged. Never regenerate `e2e/fixtures/expected/`.
- Look back applies only when `resolveSourceAction(settings)` is `"mark"` or `"delete"`, `skipExistingTodos` is `true`, and `lookBackDays > 0`. The inbox's action does not count.
- `lookBackDays`: whole number 0 to 366, default 0. `lookBackSince`: `"YYYY-MM-DD"` local date or `""`, default `""`.
- Older notes get the previous note's behaviour: `sourceAction: resolveSourceAction(settings)`, counters raised, no `keepHeadings`, no `placement`.
- Source order: previous note, older notes newest first, inbox.
- "Done in a newer note" and hiding rule-chosen Leaves apply only to `kind: "earlier"` sources.
- Existing notice texts stay as they are when only the previous note and the inbox are sources. The guard notices keep their current texts for today/previous/backlog conflicts; the new texts below are used only when the conflict is with an older note.
- `src/daily-notes.js` and `src/look-back.js` never import `moment` or read `window`.
- Work on branch `look-back`. Commit messages have no Co-Authored-By or Claude-Session line (the user's global CLAUDE.md forbids them).

## Review Focus

1. A daily-notes format with folders (`YYYY/MM/DD`) gives two older notes the same basename; their item ids must not collide (Task 4: `earlierSource` key from the path, test with two notes named `21`).
2. A Look back window reaching across a month or year boundary must include the right notes (Task 1: window test across 1 January).
3. A hand-edited `data.json` with `lookBackSince: "2026-13-40"` or `"yesterday"` must not throw or read everything: it is reset to today and no older notes are read on that run (Task 2: `settledLookBackSince` tests).
4. An older todo whose newer done copy carries a different `[rolled:: n]`, a different list marker (`*` vs `-`) or indentation must still count as done; a done copy only in an even older note must not (Task 3: `handledItemIds` tests).
5. A rollover where every older todo is handled or rule-left must not open the review (with review set to "always") and must leave today's note byte for byte (Task 4 flow test; Task 6 e2e).
