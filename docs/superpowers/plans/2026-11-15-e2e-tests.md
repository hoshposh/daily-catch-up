# End-to-End Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pnpm test:e2e`, a vitest suite that drives the running Obsidian app through the official `obsidian` CLI against the `e2e-vault` vault, and reruns every check from `.claude/manual-test-checklist.md` and the rules plan's manual steps.

**Two parts (decided):** Part 1 (Tasks 1–8) is built on `feat/e2e-tests`, a worktree at `.claude/worktrees/e2e-tests` created from `main`, and merged into `main`. Part 2 (Tasks 9–11) is done on `feat/rules` after `main` is merged into it, because the rules tests need the rules feature. `feat/e2e-tests` changes nothing in `src/`, so its build is `main`'s.

**Architecture:** Three helper modules under `e2e/helpers/`: `obsidian.js` wraps the CLI (eval, commands, polling, errors), `vault.js` guards, bootstraps and resets the vault, and `rollover.js` drives the rollover and its dialogs. A vitest global setup bootstraps once per run and checks afterwards that the repo-root `main.js` and `data.json` (the manual vault's plugin) were not touched. Test files `e2e/*.e2e.js` run one at a time. Pure parts of the helpers (output parsing, the vault safety check) have unit tests that run in `pnpm test`.

**Tech Stack:** Node (`child_process.execFile`, `fs/promises`), vitest 3, rollup, Obsidian CLI (Obsidian 1.15). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-15-e2e-tests-design.md`

## Global Constraints

- Only the vault named `e2e-vault` (or `$E2E_VAULT`) is ever written to, and only after `checkVaultSafe()` passes. Nothing is written outside its path.
- The repo-root `main.js` and `data.json` are never written by the suite. The plugin is built with `rollup -c --environment BUILD:production --file <vault>/.obsidian/plugins/daily-catch-up/main.js`; `manifest.json` and `styles.css` are copied next to it. The e2e plugin folder is a real folder, never a symlink.
- No fixed sleeps. Every wait is `waitFor()` on a condition, with a timeout and a failure message that includes the last value seen.
- `pnpm test` stays Obsidian-free: e2e test files are named `*.e2e.js` (missed by vitest's default include); only pure helper tests (`e2e/helpers/*.test.js`) join the unit run.
- No changes to `src/`. If a test cannot be written without a hook in the plugin, stop and report instead of adding one.
- An automatic run starts asynchronously after today's note is created, so `rolloverInProgress` can still be `false` before it begins. Wait for a sign that the run happened (its notice, or the review dialog) before `waitForIdle()`; never treat "idle" alone as "done" after `openToday()`.
- CLI calls go through `execFile("obsidian", [\`vault=${VAULT_NAME}\`, ...args])`, never a shell string.
- Note fixtures are written with `fs` directly (the vault is local), then the helper waits until `app.vault.getAbstractFileByPath()` sees each one.
- Expected whole-file outputs (check 1) are reviewed by the user before they are committed. Never commit generated expected files unread.
- Screenshots never fail a test. They go to `e2e/screenshots/` (gitignored).
- Commit messages: plain imperative subject, no `Co-Authored-By` or `Claude-Session` lines (the user's global CLAUDE.md).
- Run prettier only on files a task creates or edits, never repo-wide.
- Run e2e tests with `pnpm test:e2e [file]`; Obsidian must be running with `e2e-vault` open. Do not click in that window during a run.

## Review Focus

1. **Obsidian not running, or `e2e-vault` not open:** the run fails once, fast, with "Obsidian CLI could not reach vault "e2e-vault". Open it in Obsidian and keep Obsidian running.", not a timeout in every test. Unit test in Task 1 (`cliError`); global setup calls the CLI first, so the run stops there.
2. **The suite pointed at a real vault** (`E2E_VAULT=test-vault`, or a non-empty `e2e-vault` without the marker): it refuses before writing anything. Unit test in Task 2.
3. **A test that fails halfway** leaves a modal open, mobile emulation on, the dark theme on, or a rollover in progress: the next test still starts clean. Test in Task 2.
4. **A notice that disappears before it is read** (short duration, or the test is slow): the recorder still has it. Test in Task 3.
5. **Code and data with newlines, quotes and emoji** (`📅`, `"`, `\n`) sent through `eval`: they round-trip unchanged. Test in Task 1.

### Task 1: CLI helper and test runner

**Files:**

**Interfaces:**
- Produces (all from `e2e/helpers/obsidian.js`):
  - `VAULT_NAME`: `process.env.E2E_VAULT ?? "e2e-vault"`.
  - `parseOutput(stdout: string) → string`: trims; strips a leading `=> `; throws `Error` whose message contains the full output when it starts with `Error:`.
  - `cliError(err, args) → Error`: maps a failed `execFile` (ENOENT, non-zero exit, output saying the vault is unknown or the app isn't running) to `Error("Obsidian CLI could not reach vault \"<VAULT_NAME>\". Open it in Obsidian and keep Obsidian running.")` with the original output appended; otherwise an `Error` with the args and output.
  - `obsidian(args: string[], { timeout = 20000 } = {}) → Promise<string>`: runs the CLI, returns `parseOutput(stdout)`.
  - `evalJs(code: string) → Promise<string>`: `obsidian(["eval", \`code=${code}\`])`.
  - `evalJson(expr: string) → Promise<any>`: evaluates `JSON.stringify(<expr>)` and parses it; `null` for empty output.
  - `command(id: string) → Promise<void>`: `obsidian(["command", \`id=${id}\`])`.
  - `waitFor(fn: () => Promise<T>, { timeout = 10000, interval = 100, message = "condition" } = {}) → Promise<T>`: resolves with `fn()`'s first truthy result; on timeout throws `Error(\`Timed out waiting for ${message}; last value: ${JSON.stringify(last)}\`)`. An error thrown by `fn` counts as "not yet" and is reported as the last value.
  - `startAsync(body: string) → Promise<void>`: runs `window.__e2e = { done: false }; (async () => { <body> })().then(v => window.__e2e = { done: true, value: v }, e => window.__e2e = { done: true, error: String(e?.stack ?? e) })`.
  - `awaitAsync({ timeout } = {}) → Promise<any>`: `waitFor` on `window.__e2e.done`; throws the recorded error, else returns the value (must be JSON-serialisable).
  - `capturedErrors() → Promise<string[]>` and `clearErrors() → Promise<void>`: from `dev:errors` / `dev:errors clear`; an empty buffer gives `[]`.
  - `screenshot(name: string) → Promise<string>`: `dev:screenshot path=<repo>/e2e/screenshots/<name>.png`, returns that path and appends it to `e2e/screenshots/.index` (one path per line) for the end-of-run list.
  - `setMobile(on: boolean) → Promise<void>`: `dev:mobile on|off`, idempotent (check the current state with `evalJson("app.isMobile")` first; `dev:mobile` with no arg may toggle).
