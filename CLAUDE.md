# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pnpm dev          # watch mode build (dev)
pnpm build        # production build → main.js
pnpm test         # run all tests (vitest)
pnpm test -- --reporter=verbose   # run tests with details
pnpm format       # prettier format
pnpm test:e2e     # end-to-end tests in Obsidian (needs Obsidian open with e2e-vault)
```

Run a single test by name:

```bash
pnpm test -- -t "single todo element"
```

## Architecture

This is Daily Catch-Up (plugin id `daily-catch-up`), an [Obsidian](https://obsidian.md) plugin. Obsidian plugins must ship as a CommonJS bundle at `main.js` (built by rollup from `src/index.js`). The `obsidian` import is external (provided by Obsidian at runtime).

**Core files:**

- `src/index.js` — `RolloverTodosPlugin` class (extends `Plugin`). Handles plugin lifecycle (`onload`), vault event registration, commands ("Roll over todos now", "Undo last rollover"), and the top-level `rollover()` orchestration logic.
- `src/get-todos.js` — `TodoParser` class + `getTodos()` / `getTodosAndSkipped()` exports, plus the section helpers `getSections()` (todos grouped by full heading ancestry), `removeEmptiedHeadings()` (drops the headings a deletion emptied, not ones that were already empty), `hasHeading()` and `insertUnderHeading()`. Pure logic on arrays of markdown lines. Uses `Intl.Segmenter` for correct Unicode grapheme cluster handling (emoji, combining characters in checkbox content). A checkbox line carrying the `#rolled` tag (`ROLLED_MARKER`, `hasRolledMarker()`: the marker the Journals plugin's own rollover writes) is never rolled, and neither is anything nested under it, blank lines included. The optional `isIgnored(line, headingPath)` option of `getSections()` (wired to "Not a todo" rules) skips an open todo line the same way. Also home to the shared line helpers `LIST_PREFIX`, `TAG_END` and `headingText()`.
- `src/source-action.js` — pure `applySourceAction()` for what happens to the previous day's note after rollover (`none` / `delete` / `mark`), acting on line positions from `getSections()` (`incompleteLineIndices`, `skippedLineIndices`), never on line text, plus settings helpers (`resolveSourceAction`, `migrateSourceActionSettings`, `normalizeMarker`, `effectiveDoneStatusMarkers`), `markCancelled()` (the Cancel outcome's checkbox change) and `isCancelAvailable()` (Cancel is offered only when the cancel marker is a done marker).
- `src/insert-sections.js` — pure `insertSections()`: puts each section's todos into today's note under the template heading, or under the headings they had in the previous note when there is none, reusing existing headings and creating missing ones.
- `src/insert-todos.js` — pure `dedupeAgainstExisting()` (skip todos already in today's note), `verifyTodosPresent()` (Templater safeguard) and `dropEmptyTodos()` (with `recordDropped`, a section also carries `droppedLineIndices` / `droppedTodos`, the empty todos dropped from it).
- `src/rolled-count.js` — pure helpers for the inline `[rolled:: n]` counter: `parseRolledCount`, `setRolledCount`, `stripRolledCount`, and `insertField` (also used for `[from:: …]`). A field goes before the first Obsidian Tasks emoji field (so Tasks still reads its fields from the end of the line), else before a trailing block id, else at the end.
- `src/rollover-items.js` — pure review logic: `toItems()` groups a section's todos into items (a todo plus nested lines; skipped completed children and dropped empty todos indented under the head do not split an item), `isStale()`, `defaultDecisions()`, `needsReview()`, `countOutcomes()`, `applyDecisions()` (turns decisions into sections to insert, backlog items and the line indices to move, cancel and delete), `bumpRolledCounts()`, `skippedLinesToDelete()`, and label/summary helpers for the dialog. A skipped or dropped line belongs to the item holding the nearest line above it that is indented less (walking up through skipped and dropped lines, never past a line the parser did not find), or to no item; delete removes it unless it belongs to a Cancel or Leave item. Outcomes are `"roll"`, `"backlog"`, `"cancel"`, `"leave"`.
- `src/rollover-plan.js` — the Obsidian-free decision stage of `rollover()`, shared by `index.js` and `rollover-flow.test.js`: `planDecisions()` (drop empty todos, `toItems()`, default decisions), `applyPlan()` (`applyDecisions()`, `skippedLinesToDelete()`, outcome counts) and `planInsert()` (dedupe against today's note, `bumpRolledCounts()`).
- `src/rules.js` — pure rule logic: `EXAMPLE_RULES` (nine, all switched off), `ruleProblem()` (why a rule can't be used), `ruleMatches()`, `isIgnoredByRules()` (for the parser), `ruleResult()` (an item's `outcome`, `noStale` and `moveTo`, each with the rule that set it: first match per kind wins, kinds combine, an unavailable outcome falls back without the next rule taking over), and the settings-facing `ruleLabel()`, `ruleSummary()`, `ruleNote()`, `newRuleId()`, `MATCH_LABELS`, `EFFECT_LABELS`.
- `src/backlog.js` — pure `appendToBacklog()` / `backlogLines()`: adds parked items to the backlog note's content under a heading (created when missing) or at the end, with the counter stripped and `[from:: [[source note]]]` added.
- `src/template-headings.js` — pure helpers for the template heading setting (`extractHeadings`, `headingOptions`).
- `src/settings-dependencies.js` — pure `dependentSettingStates()`: for each dependent setting (`DEPENDENT_SETTINGS`), whether it applies and, if not, the reason shown in place of its description; plus `cancelMarkerNote()`.
- `src/settings-text.js` — the settings tab's text: `SETTING_GROUPS` (seven groups with their `?` help, `**bold**` markup split by `helpSegments()`), `SETTING_LABELS` and the one-line `SETTING_DESCRIPTIONS`.
- `src/ui/RolloverSettingTab.js` — Obsidian `PluginSettingTab` for the settings panel: renders the seven groups from `settings-text.js`, with dependent settings indented under their parent and a `?` help panel per group. After every change `refreshDependents()` greys out the settings that don't apply (from `settings-dependencies.js`) in place, so the page never re-renders or jumps.
- `src/ui/UndoModal.js` — Obsidian `Modal` for the undo confirmation dialog (also restores or deletes the backlog note). Restores notes with `vault.process()`.
- `src/ui/ReviewModal.js` — Obsidian `Modal` for the review dialog: one dropdown per item, section and global shortcuts, a live summary, and badges naming the rule behind an item's default and its move target. `openAndWait()` resolves with the decisions on Apply and `null` otherwise. UI only; logic lives in `rollover-items.js`.
- `src/ui/RuleModal.js` — Obsidian `Modal` for adding or editing one rule (match, value, effect, target heading), validated live with `ruleProblem()`. `openAndWait()` resolves with the rule on Save and `null` otherwise. The settings tab's Rules group (rows with switch, summary, `ruleNote()`, edit / up / down / delete, then Add rule) re-renders only its own container.
- `styles.css` — styles for the review dialog and the settings tab's indented dependents and help panels (theme CSS variables only, wraps at phone width). Shipped with the release next to `main.js` and `manifest.json`.

**Plugin settings** (defaults in `loadSettings`):

- `templateHeading` — heading to insert todos under (or `"none"` for end of file)
- `onRolloverSourceAction` — `"none"` (default), `"delete"` or `"mark"`: what to do with rolled todos on the previous day's note (replaces the old `deleteOnComplete` boolean, which is migrated to `"delete"`)
- `rolloverSourceMarker` — checkbox character used by `"mark"` (default `">"`); counts as a done marker while marking, without changing `doneStatusMarkers`
- `moveNestedItemsOnMark` — with `"mark"` and `rolloverChildren`, keep only the marked todo in the previous day's note and remove the rolled items nested under it (they moved to today's note); completed children stay when `skipCompletedChildren` is on
- `skipExistingTodos` — don't roll over todos (with their children) that today's note already has
- `ignoreBlockquotes` — don't roll over todos inside blockquotes/callouts
- `skipCompletedChildren` — with `rolloverChildren`, leave completed child todos out (removed with their parent when deleting)
- `removeEmptyTodos` — skip empty `- [ ]` items
- `rolloverChildren` — include indented child items under a todo
- `rolloverOnFileCreate` — auto-trigger on vault `create` event
- `doneStatusMarkers` — string of characters treated as "done" (default `"xX-"`)
- `reviewOnAutoRollover` — `"off"` (default), `"stale"` or `"always"`: whether an automatic rollover opens the review dialog (the "Review and roll over todos…" command always does)
- `cancelMarker` — checkbox character for the Cancel outcome (default `"-"`); Cancel is offered only when it is one of the done markers (`isCancelAvailable`), and `effectiveDoneStatusMarkers` is not changed for it
- `trackRolloverCount` — default `false`: write `[rolled:: n]` on each rolled todo, raised by 1 per rollover
- `staleAfterRollovers` — default `5`: a todo is stale once its count is at least this (0 disables); only used with `trackRolloverCount`
- `staleBehavior` — `"keep"` (default) or `"backlog"`: default outcome of stale todos, and what happens to them when no review is shown (needs a backlog note)
- `backlogNotePath` — default `""`: note that receives Backlog items; empty disables the Backlog outcome. Cannot be today's or the previous note
- `backlogHeading` — default `""`: heading in the backlog note to add items under (empty = end of note); text that does not match `/^#{1,6}\s/` gets a `## ` prefix
- `rules` — ordered list of `{ id, enabled, match: "tag"|"heading"|"regex", value, effect: "roll"|"backlog"|"cancel"|"leave"|"ignore"|"noStale"|"move", target? }`. Seeded with `EXAMPLE_RULES` (all off) when the stored settings have no `rules` key, never reseeded
- `leadingNewLine` — blank line between a heading and the first todos inserted under it, and before a heading the rollover adds; todos added to an existing list continue it without one

**Rollover flow:** On daily note creation (or a command), `rollover()` validates the file is today's daily note (created within 5 seconds); while another rollover is still running (`rolloverInProgress`, e.g. its dialog is open) an automatic run returns silently and a command shows a notice. `rolloverDailyNote()` then finds the previous daily note via `getLastDailyNote()`, and groups its unfinished todos by heading with `getSections()`. Review stage (`planDecisions()`): empty todos are dropped with `removeEmptyTodos`, `toItems()` groups the todos into items, each gets its `ruleResult()` as `item.rule`, `defaultDecisions()` picks an outcome per item (a rule's outcome first; otherwise Roll, except stale items under `staleBehavior: "backlog"` when a backlog note is set; `isStale()` is false for No stale count items), and `ReviewModal` lets the user change them when the "Review and roll over todos…" command was used or `needsReview()` says so for an automatic run. It only opens when there are items, and closing it abandons the rollover with nothing written. `applyPlan()` (`applyDecisions()`) turns the decisions into the sections to insert (Roll items only), the items for the backlog, and the line positions to cancel, delete or leave. Today's note is read after the review, in the same `vault.process()` that writes it, so planning and writing see the same content. Roll items a Move to heading rule sends elsewhere leave their section for a moved section (`moveTo`), which `insertSections()` puts under the first heading with that text anywhere in today's note, or under a new one at the end, ignoring the template heading. The Roll sections are inserted with `insertSections()` (under the template heading, or under their own recreated headings when there is none), optionally skipping todos today's note already has, with `[rolled:: n]` raised by `bumpRolledCounts()` when `trackRolloverCount` is on, except for No stale count items (`noStaleLineIndices`) (both in `planInsert()`). "Not a todo" lines never get this far: the parser skips them. Backlog items are then appended with `appendToBacklog()` (the note and its folder are created when missing; if the write fails the previous note is left untouched). Last, the previous day's note changes in one `vault.process()`: Cancel items are marked first with `markCancelled()` (never deleted), then the configured source action (`delete` / `mark`) runs on Roll and Backlog items only. Both use the line positions of the note as it was parsed, which stay valid because marking only rewrites checkboxes. Leave items are untouched. If Templater is enabled and the action is destructive, it first waits 3 seconds and checks that the inserted todos survived. Undo history is kept for 2 minutes and also snapshots the backlog note (undo deletes it when the rollover created it); with Templater enabled only the previous day's note and the backlog note are snapshotted.

**Testing:** Tests (`pnpm test`) cover the pure modules: `src/get-todos.test.js`, `src/source-action.test.js`, `src/insert-todos.test.js`, `src/insert-sections.test.js`, `src/template-headings.test.js`, and `src/rolled-count.test.js`, `src/rollover-items.test.js`, `src/backlog.test.js`, `src/settings-dependencies.test.js`, `src/settings-text.test.js`, `src/rules.test.js`, and `src/rollover-flow.test.js` (the Obsidian-free parts of `rollover()` run end to end, through the same `rollover-plan.js` calls as `index.js`). The vault/UI logic in `index.js` and `src/ui/` (including the review dialog and the settings tab) needs Obsidian, so unit tests cannot reach it; the end-to-end tests below cover it. Keep logic in the pure modules, where it can be unit tested.

**End-to-end tests:** `pnpm test:e2e` (`vitest.e2e.config.js`, files run one at a time) drives the running Obsidian app through the official `obsidian` CLI against a dedicated vault named `e2e-vault` (override with `E2E_VAULT`), so it covers what the unit tests cannot: `index.js` and `src/ui/`. Obsidian must be running with that vault open.

- `e2e/helpers/obsidian.js` — the CLI wrapper: `evalJs()` / `evalJson()` (code runs in the app, `app` is global), `waitFor()` (polls a condition; the suite never sleeps for a fixed time), `startAsync()` / `awaitAsync()` (the CLI only returns promises that are already settled), `setViewportWidth()` (phone width through DevTools device metrics; `dev:mobile` reloads the app and keeps the window's width), `screenshot()`, `capturedErrors()` (uncaught errors from `dev:errors` plus `console.error` messages from `dev:console`, which is how the plugin logs its own failures). The CLI exits 0 on errors, so `parseOutput()` turns `Error:` and `Vault not found.` output into exceptions, after skipping the `[level] ` console lines an `eval` prints before its result. `assertAppReachable()` checks the app's CLI socket before the first call: without a running Obsidian, the `obsidian` binary would launch the app and hang instead of answering.
- `e2e/helpers/vault.js` — `checkVaultSafe()` / `guardVault()` (writes only to a vault with the `.e2e-vault` marker, adopting an empty one), `bootstrap()` (builds into the vault's own plugin folder, never the repo-root `main.js`, which the manual test vault loads through a symlink), `reset()` (before each test: closes dialogs, including the settings window, which is a popout window in Obsidian 1.15; deletes every note through `app.vault`; writes the test's notes and `data.json` with the plugin disabled, so writing today's note does not start a rollover), `standardNotes()`, `CHECKLIST_PROFILE`, `day()`.
- `e2e/helpers/rollover.js` — drives a rollover as a user does (`openToday()` via the CLI's `daily`, `runCommand()`) and reads the result: review dialog rows, `setOutcome()`, `clickButton()`, `pressEscape()`, recorded notices (notices don't expire while the window is in the background, so `reset()` clears them and a recorder keeps their text), `horizontalOverflow()`.
- `e2e/helpers/settings-tab.js` — drives the settings tab and the rule dialog: `openSettings()`, `ruleRows()`, `toggleRule()`, `clickRuleControl()`, `fillRuleDialog()`, `ruleDialog()`, `setTextSetting()`. Every query runs in `SETTINGS_DOC` (`app.setting.modalEl.ownerDocument`): the settings window is a popout window with its own document, and the rule dialog opens there too. The popout cannot be narrower than 600 px, so phone-width checks call `setViewportWidth(375)` and then `setMobile(true)`, which shows the settings in the main window with Obsidian's phone layout (in that order: the reload picks the phone layout only when the window is already narrow).
- `e2e/setup.js` — global setup: bootstraps once per run, fails the run if the repo-root `main.js` or `data.json` changed, and lists the screenshots to review (`e2e/screenshots/`, gitignored).
- `e2e/fixtures/notes/` — the previous-day fixture and today's template. `e2e/fixtures/expected/` — the baseline outputs, generated from `main`'s code with `E2E_UPDATE_EXPECTED=1` and reviewed by hand; never regenerate them to make a failing baseline pass.
- Tests: `e2e/cli.e2e.js`, `e2e/vault.e2e.js` (the helpers themselves), `e2e/guards.e2e.js` (cancelled and refused rollovers change nothing), `e2e/baseline.e2e.js` (output matches `main` with newer features off), `e2e/outcomes.e2e.js` (the four outcomes, undo), `e2e/aging.e2e.js` (stale todos, counter placement), `e2e/layout.e2e.js` (review dialog at phone width), `e2e/rules.e2e.js` (rule defaults, badges and moves in the review; Not a todo and No stale count in a real rollover; examples reseeded), `e2e/settings.e2e.js` (the Rules settings group and rule dialog, including that the page keeps its scroll position when rules change). The pure helper parts have unit tests in `e2e/helpers/*.test.js`, which run with `pnpm test`.

Plans write an e2e test where they would have written a manual check in the test vault. Keep a manual step only for judging a screenshot.

## Origins and upstream

Daily Catch-Up is an independent plugin that started as a fork of `git@github.com:lumoe/obsidian-rollover-daily-todos.git` (Rollover Daily Todos, the upstream Obsidian community plugin). Upstream changes can still be adopted selectively. The GitHub repository is `hoshposh/daily-catch-up` (renamed from `hoshposh/obsidian-rollover-daily-todos` on 2026-11-10; GitHub redirects the old URL). It is still a GitHub fork of upstream.

**Branching strategy:**

- `main` — primary branch. Upstream's `master` changes are selectively cherry-picked here.
- `master` — tracks the upstream `master` branch (kept in sync to make cherry-picking straightforward).
- `release/v1.3.0` — upstream's unreleased branch, kept for reference. The options worth having were already adapted (see `docs/upstream-v1.3.0-triage.md`).

When pulling in upstream changes: fetch from upstream into `master`, then cherry-pick individual commits onto `main`. Avoid bulk-merging `master` → `main` to stay in control of what behavioral changes are adopted. Upstream still uses the old plugin id, command ids, command name and console prefix, so adapt those in anything you cherry-pick.
