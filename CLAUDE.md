# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pnpm dev          # watch mode build (dev)
pnpm build        # production build → main.js
pnpm test         # run all tests (vitest)
pnpm test -- --reporter=verbose   # run tests with details
pnpm format       # prettier format
pnpm test:e2e     # end-to-end tests in Obsidian (needs Obsidian open with e2e-vault)
pnpm test:e2e e2e/rules.e2e.js   # one e2e file (`pnpm test:e2e -- <file>` runs them all)
pnpm demo <name>  # record e2e/demos/**/<name>.demo.js as e2e/demos/out/<name>.gif (needs Obsidian open with e2e-vault)
```

Run a single test by name:

```bash
pnpm test -- -t "single todo element"
```

## Architecture

This is Daily Catch-Up (plugin id `daily-catch-up`), an [Obsidian](https://obsidian.md) plugin. Obsidian plugins must ship as a CommonJS bundle at `main.js` (built by rollup from `src/index.js`). The `obsidian` import is external (provided by Obsidian at runtime).

**Core files:**

- `src/index.js` — `RolloverTodosPlugin` class (extends `Plugin`). Handles plugin lifecycle (`onload`), vault event registration, commands ("Roll over todos now", "Undo last rollover"), and the top-level `rollover()` orchestration logic.
- `src/get-todos.js` — `TodoParser` class + `getTodos()` / `getTodosAndSkipped()` exports, plus the section helpers `getSections()` (todos grouped by full heading ancestry), `removeEmptiedHeadings()` (drops the headings a deletion emptied, not ones that were already empty), `hasHeading()` and `insertUnderHeading()`. Pure logic on arrays of markdown lines. Uses `Intl.Segmenter` for correct Unicode grapheme cluster handling (emoji, combining characters in checkbox content). A checkbox line carrying the `#rolled` tag (`ROLLED_MARKER`, `hasRolledMarker()`: the marker the Journals plugin's own rollover writes) is never rolled, and neither is anything nested under it, blank lines included. The optional `isIgnored(line, headingPath)` option of `getSections()` (wired to "Not a todo" rules) skips an open todo line the same way. Also home to the shared line helpers `LIST_PREFIX`, `TAG_END` and `headingText()`.
- `src/source-action.js` — pure `applySourceAction()` for what happens to a source note after rollover (`none` / `delete` / `mark`), acting on line positions from `getSections()` (`incompleteLineIndices`, `skippedLineIndices`), never on line text; with `keepHeadings` (passed by `writeSource()` from the source, `true` for the inbox) delete only removes the lines and keeps the headings they emptied. Plus settings helpers (`resolveSourceAction`, `migrateSourceActionSettings`, `normalizeMarker`, `effectiveDoneStatusMarkers`), `markCancelled()` (the Cancel outcome's checkbox change) and `isCancelAvailable()` (Cancel is offered only when the cancel marker is a done marker).
- `src/insert-sections.js` — pure `insertSections()`: puts each section's todos into today's note under the template heading, or under the headings they had in the previous note when there is none, reusing existing headings and creating missing ones.
- `src/insert-todos.js` — pure `dedupeAgainstExisting()` (skip todos already in today's note), `verifyTodosPresent()` (Templater safeguard) and `dropEmptyTodos()` (with `recordDropped`, a section also carries `droppedLineIndices` / `droppedTodos`, the empty todos dropped from it).
- `src/rolled-count.js` — pure helpers for the inline `[rolled:: n]` counter: `parseRolledCount`, `setRolledCount`, `stripRolledCount`, and `insertField` (also used for `[from:: …]`). A field goes before the first Obsidian Tasks emoji field (so Tasks still reads its fields from the end of the line), else before a trailing block id, else at the end.
- `src/rollover-items.js` — pure review logic: `toItems()` groups a section's todos into items (a todo plus nested lines; skipped completed children and dropped empty todos indented under the head do not split an item), `isStale()`, `defaultDecisions()`, `needsReview()`, `countOutcomes()`, `applyDecisions()` (turns decisions into sections to insert, backlog items and the line indices to move, cancel and delete), `bumpRolledCounts()`, `skippedLinesToDelete()`, `rebaseSections()` (a todo whose parent line does not go to the same place starts at column 0, its nested lines shifted with it; one nested under a todo that goes there too keeps its indentation), and label/summary helpers for the dialog. A skipped or dropped line belongs to the item holding the nearest line above it that is indented less (walking up through skipped and dropped lines, never past a line the parser did not find), or to no item; delete removes it unless it belongs to a Cancel or Leave item. Outcomes are `"roll"`, `"backlog"`, `"cancel"`, `"leave"`.
- `src/rollover-plan.js` — the Obsidian-free decision stage of `rollover()`, shared by `index.js` and `rollover-flow.test.js`: `planDecisions()` (drop empty todos, `toItems()`, default decisions), `applyPlan()` (`applyDecisions()`, `skippedLinesToDelete()`, outcome counts) and `planInsert()` (dedupe against today's note, `bumpRolledCounts()`, then `rebaseSections()` with the previous note's lines).
- `src/rollover-sources.js` — the Obsidian-free orchestration of a rollover over a list of source notes, on top of `rollover-plan.js`, shared by `index.js` and `rollover-flow.test.js`. A source is `{ key, kind, name, file, content, lines, sections, sourceAction, keepHeadings?, countRollover?, placement? }`: `key` prefixes its item ids (`""` for the previous daily note, so its ids stay `"0:0"` etc.; any other key must end in a non-digit separator such as `"inbox/"`, and `planSources()` throws on a duplicate id), `kind` is what the source is (`"previous"` or `"inbox"`), `name` is the note's basename (dialog title and "From …" rows, "left in …", `[from:: [[…]]]`), `sourceAction` is `resolveSourceAction()` for the previous note; `keepHeadings` makes delete keep the headings it empties, `countRollover: false` keeps every item's `[rolled:: n]` as it is, and a `placement` heading becomes each item's `moveTo` unless a Move to heading rule set one; a missing field means the previous note's behaviour. `inboxSource({ file, content, lines, sections, settings })` builds the inbox's source: `{ key: "inbox/", kind: "inbox", name: file.basename, …, sourceAction: inboxSourceAction(settings), keepHeadings: true, countRollover: false, placement: normalizeHeading(inboxHeading) or null }`, where `inboxSourceAction()` is `"mark"` for `"mark"` and `"delete"` for anything else (never `"none"`, or the inbox would be pulled every day). `inboxPathConflicts({ inboxPath, todayPath, previousPath, backlogPath })` is the inbox guard (a null path is not compared) and `INBOX_GUARD_NOTICE` its text. `planSources()` runs `planDecisions()` per source and joins the items and default decisions; `applySources()` runs `applyPlan()` per source (`perSource`), tags each backlog item with its source's `sourceName` and adds up the outcome counts; `insertSources()`, called inside today's `vault.process()`, runs `planInsert()` and `insertSections()` per source against the content the earlier sources left (skipping `insertSections()` when nothing is left, so the note stays byte for byte) and returns per source `todosAlreadyPresent`, `duplicateTodos`, `retainedLineIndices` and `insertedTodos`, plus `templateHeadingNotFound`; `writeSource({ content, source, decided, retainedLineIndices, settings }) → { content, changed }` is what one source note becomes, called inside its `vault.process()` once the "edited meanwhile" check passed: `markCancelled()` (cancel marker, effective done markers), then, unless `sourceAction` is `"none"`, `applySourceAction()` (source marker, the raw `doneStatusMarkers`, `moveNested` = `moveNestedItemsOnMark && rolloverChildren`, `retainLineIndices`), with `settings` the plugin settings; `rolloverNotice()` builds the notice text from the counts (per source `kind` and `rolledCount`: the rolled line names each non-previous source that contributed, "(2 from Inbox)"; one empty-todo line summed over the sources that delete; one "left in {name}" line per source). The other notices name the sources through `sourceLabel()` ("the previous day's note", "the inbox note '{name}'"): `sourceUnchangedNotice(source)` (edited meanwhile), `templaterNotice(sources)`, `backlogFailedNotice({ backlogPath, error, todosAdded, sources })` and `sourceWriteFailedNotice(source, error)`; with the previous note as the only source they return the texts the plugin always showed. The sources are the previous daily note and, when set, the inbox note.
- `src/rules.js` — pure rule logic: `EXAMPLE_RULES` (nine, all switched off), `ruleProblem()` (why a rule can't be used), `ruleMatches()`, `isIgnoredByRules()` (for the parser), `ruleResult()` (an item's `outcome`, `noStale` and `moveTo`, each with the rule that set it: first match per kind wins, kinds combine, an unavailable outcome falls back without the next rule taking over), and the settings-facing `ruleLabel()`, `ruleSummary()`, `ruleNote()`, `ruleDraft()` (a hand-edited rule coerced into what the rule dialog can show and save), `newRuleId()`, `MATCH_LABELS`, `EFFECT_LABELS`.
- `src/backlog.js` — pure `appendToBacklog()` / `backlogLines()`: adds parked items to the backlog note's content under a heading (created when missing) or at the end, with the counter stripped and `[from:: [[source note]]]` added.
- `src/template-headings.js` — pure helpers for the template heading setting (`extractHeadings`, `headingOptions`).
- `src/settings-dependencies.js` — pure `dependentSettingStates()`: for each dependent setting (`DEPENDENT_SETTINGS`), whether it applies and, if not, the reason shown in place of its description; plus `cancelMarkerNote()`.
- `src/settings-text.js` — the settings tab's text: `SETTING_GROUPS` (eight groups with their `?` help, `**bold**` markup split by `helpSegments()`), `SETTING_LABELS` and the one-line `SETTING_DESCRIPTIONS`.
- `src/ui/RolloverSettingTab.js` — Obsidian `PluginSettingTab` for the settings panel: renders the eight groups from `settings-text.js`, with dependent settings indented under their parent and a `?` help panel per group. After every change `refreshDependents()` greys out the settings that don't apply (from `settings-dependencies.js`) in place, so the page never re-renders or jumps. The Rules group (`renderRules()`) rebuilds only itself, and builds the new rows off the page before swapping them in: emptying it first made the page jump when a rule was moved.
- `src/ui/UndoModal.js` — Obsidian `Modal` for the undo confirmation dialog: restores today's note and each source note in the undo entry's `sources` list (each listed by file name), and restores or deletes the backlog note; its description names the inbox note only when one is set. Restores notes with `vault.process()`.
- `src/ui/ReviewModal.js` — Obsidian `Modal` for the review dialog, taking `sources: [{ name, sections, items }]` (a source without items is not shown; with one source it is titled `Roll over from {name}`; with more it is titled `Roll over todos` and each source starts with a heading row `From {name}` (class `rollover-review-source`) with its own All roll / All leave, followed by its sections; the top "All todos" row covers every source): one dropdown per item, section and global shortcuts, a live summary, and badges naming the rule behind an item's default and its move target. `openAndWait()` resolves with the decisions on Apply and `null` otherwise. UI only; logic lives in `rollover-items.js`.
- `src/ui/RuleModal.js` — Obsidian `Modal` for adding or editing one rule (match, value, effect, target heading), validated live with `ruleProblem()`. `openAndWait()` resolves with the rule on Save and `null` otherwise. The settings tab's Rules group (rows with switch, summary, `ruleNote()`, edit / up / down / delete, then Add rule) re-renders only its own container.
- `styles.css` — styles for the review dialog and the settings tab's indented dependents and help panels (theme CSS variables only, wraps at phone width). Shipped with the release next to `main.js` and `manifest.json`.

**Plugin settings** (defaults in `loadSettings`):

- `templateHeading` — heading to insert todos under (or `"none"` for end of file)
- `onRolloverSourceAction` — `"none"` (default), `"delete"` or `"mark"`: what to do with rolled todos on the previous day's note (replaces the old `deleteOnComplete` boolean, which is migrated to `"delete"`)
- `rolloverSourceMarker` — checkbox character used by `"mark"` (default `">"`); counts as a done marker while marking, without changing `doneStatusMarkers`
- `moveNestedItemsOnMark` — with `"mark"` and `rolloverChildren`, keep only the marked todo in the previous day's note and remove the rolled items nested under it (they moved to today's note); completed children stay when `skipCompletedChildren` is on
- `skipExistingTodos` — don't roll over todos (with their children) that today's note already has
- `ignoreBlockquotes` — don't roll over todos inside blockquotes/callouts
- `skipCompletedChildren` — with `rolloverChildren`, leave completed child todos out (removed with their parent when deleting)
- `removeEmptyTodos` — skip empty `- [ ]` items
- `rolloverChildren` — include indented child items under a todo
- `rolloverOnFileCreate` — auto-trigger on vault `create` event
- `doneStatusMarkers` — string of characters treated as "done" (default `"xX-"`)
- `reviewOnAutoRollover` — `"off"` (default), `"stale"` or `"always"`: whether an automatic rollover opens the review dialog (the "Review and roll over todos…" command always does)
- `cancelMarker` — checkbox character for the Cancel outcome (default `"-"`); Cancel is offered only when it is one of the done markers (`isCancelAvailable`), and `effectiveDoneStatusMarkers` is not changed for it
- `trackRolloverCount` — default `false`: write `[rolled:: n]` on each rolled todo, raised by 1 per rollover
- `staleAfterRollovers` — default `5`: a todo is stale once its count is at least this (0 disables); only used with `trackRolloverCount`
- `staleBehavior` — `"keep"` (default) or `"backlog"`: default outcome of stale todos, and what happens to them when no review is shown (needs a backlog note)
- `backlogNotePath` — default `""`: note that receives Backlog items; empty disables the Backlog outcome. Cannot be today's or the previous note
- `backlogHeading` — default `""`: heading in the backlog note to add items under (empty = end of note); text that does not match `/^#{1,6}\s/` gets a `## ` prefix
- `inboxNotePath` — default `""`: the inbox note whose open todos every rollover pulls in (`.md` added when missing, like the backlog note); empty turns the inbox off. Cannot be today's note, the previous daily note or the backlog note
- `inboxSourceAction` — `"delete"` (default) or `"mark"`: what happens to pulled todos in the inbox (no `"none"`; any other stored value counts as `"delete"`). Mark uses `rolloverSourceMarker` and `moveNestedItemsOnMark`, like the previous note; delete keeps the inbox's headings and the note itself
- `inboxHeading` — default `""`: heading in today's note for inbox todos, used like a Move to heading target (`normalizeHeading()`); empty puts them where rolled todos go
- `rules` — ordered list of `{ id, enabled, match: "tag"|"heading"|"regex", value, effect: "roll"|"backlog"|"cancel"|"leave"|"ignore"|"noStale"|"move", target? }`. Seeded with `EXAMPLE_RULES` (all off) when the stored settings have no `rules` key, never reseeded
- `leadingNewLine` — blank line between a heading and the first todos inserted under it, and before a heading the rollover adds; todos added to an existing list continue it without one

**Rollover flow:** On daily note creation (or a command), `rollover()` validates the file is today's daily note (created within 5 seconds); while another rollover is still running (`rolloverInProgress`, e.g. its dialog is open) an automatic run returns silently and a command shows a notice. `rolloverDailyNote()` then finds the previous daily note via `getLastDailyNote()` and the inbox note (`getInboxPath()`, `null` when `inboxNotePath` is empty), groups each one's unfinished todos by heading with `getSections()` (same options for both), and builds the list of sources from them, the previous note first (`rollover-sources.js`; a note without open todos is dropped, and an empty list ends the rollover silently). With no previous daily note the rollover ends at once unless an inbox is set; with one set, a missing previous note or one without open todos does not stop the inbox's todos. While the sources are built, the inbox guard (`inboxPathConflicts()`: the inbox is today's note, `lastDailyNote?.path` or the backlog note when one is set) stops the rollover with `INBOX_GUARD_NOTICE` before the backlog guard runs, so an inbox that is also the backlog note gets this notice and not the backlog one; a missing inbox note is skipped without a notice. After planning, the backlog guard compares the backlog note with today's note and `lastDailyNote` itself (whether or not it is a source; skipped when there is none). Each source is planned on its own (`planSources()`), the dialog and `needsReview()` see all items together, the decisions are applied per source (`applySources()`), today's note gets each source's todos in turn (`insertSources()`), and each source note is written in its own `vault.process()` in list order. Review stage (`planDecisions()`, per source): empty todos are dropped with `removeEmptyTodos`, `toItems()` groups the todos into items, each gets its `ruleResult()` as `item.rule`, `defaultDecisions()` picks an outcome per item (a rule's outcome first; otherwise Roll, except stale items under `staleBehavior: "backlog"` when a backlog note is set; `isStale()` is false for No stale count items), and `ReviewModal` lets the user change them when the "Review and roll over todos…" command was used or `needsReview()` says so for an automatic run. It only opens when there are items, and closing it abandons the rollover with nothing written. `applyPlan()` (`applyDecisions()`) turns the decisions into the sections to insert (Roll items only), the items for the backlog, and the line positions to cancel, delete or leave. Today's note is read after the review, in the same `vault.process()` that writes it, so planning and writing see the same content. Roll items a Move to heading rule sends elsewhere leave their section for a moved section (`moveTo`), which `insertSections()` puts under the first heading with that text anywhere in today's note, or under a new one at the end, ignoring the template heading. The Roll sections are inserted with `insertSections()` (under the template heading, or under their own recreated headings when there is none), optionally skipping todos today's note already has, with `[rolled:: n]` raised by `bumpRolledCounts()` when `trackRolloverCount` is on, except for No stale count items (`noStaleLineIndices`), and with each todo whose parent stays behind or goes elsewhere re-based to column 0 (`rebaseSections()`) (all in `planInsert()`). "Not a todo" lines never get this far: the parser skips them. Backlog items are then appended with `appendToBacklog()` (the note and its folder are created when missing; if the write fails every source note is left untouched, with `backlogFailedNotice()`). Last, each source note (the previous day's note, then the inbox) changes in its own `vault.process()`, with its own "edited meanwhile" check, through `writeSource()`: Cancel items are marked first with `markCancelled()` (never deleted), then the configured source action (`delete` / `mark`) runs on Roll and Backlog items only. Both use the line positions of the note as it was parsed, which stay valid because marking only rewrites checkboxes. Leave items are untouched. A source edited meanwhile is left unchanged with `sourceUnchangedNotice()`. A source whose `vault.process()` throws is logged (`console.error`), gets `sourceWriteFailedNotice()`, no undo entry and no cancelled count, and the loop goes on with the next source; the loop and the final notice sit in a `try` whose `finally` records the undo entry, so whatever was written stays undoable. If Templater is enabled and a source's action is destructive, it first waits 3 seconds and checks that the inserted todos survived (else `templaterNotice(sources)`, and no source is touched). The notice text comes from `rolloverNotice()`. Undo history (`{ today, backlog, sources: [{ file, oldContent }] }`, `sources` holding each source note the rollover changed) is kept for 2 minutes and also snapshots the backlog note (undo deletes it when the rollover created it); with Templater enabled only the source notes (previous day's note, inbox) and the backlog note are snapshotted.

**Testing:** Tests (`pnpm test`) cover the pure modules: `src/get-todos.test.js`, `src/source-action.test.js`, `src/insert-todos.test.js`, `src/insert-sections.test.js`, `src/template-headings.test.js`, and `src/rolled-count.test.js`, `src/rollover-items.test.js`, `src/backlog.test.js`, `src/settings-dependencies.test.js`, `src/settings-text.test.js`, `src/rules.test.js`, `src/rollover-sources.test.js`, and `src/rollover-flow.test.js` (the Obsidian-free parts of `rollover()` run end to end, through the same `rollover-sources.js` calls as `index.js`). The vault/UI logic in `index.js` and `src/ui/` (including the review dialog and the settings tab) needs Obsidian, so unit tests cannot reach it; the end-to-end tests below cover it. Keep logic in the pure modules, where it can be unit tested.

**End-to-end tests:** `pnpm test:e2e` (`vitest.e2e.config.js`, files run one at a time) drives the running Obsidian app through the official `obsidian` CLI against a dedicated vault named `e2e-vault` (override with `E2E_VAULT`), so it covers what the unit tests cannot: `index.js` and `src/ui/`. Obsidian must be running with that vault open.

- `e2e/helpers/obsidian.js` — the CLI wrapper: `evalJs()` / `evalJson()` (code runs in the app, `app` is global), `waitFor()` (polls a condition; the suite never sleeps for a fixed time), `startAsync()` / `awaitAsync()` (the CLI only returns promises that are already settled), `setViewportWidth()` (narrows the main window through DevTools device metrics), `setMobile()` (Obsidian's mobile emulation: switching it reloads the app and keeps the window's width, and the setting survives restarts; call `setViewportWidth()` first to get the phone layout), `screenshot()`, `capturedErrors()` (uncaught errors from `dev:errors` plus `console.error` messages from `dev:console`, which is how the plugin logs its own failures). The CLI exits 0 on errors, so `parseOutput()` turns `Error:` and `Vault not found.` output into exceptions, after skipping the `[level] ` console lines an `eval` prints before its result. `assertAppReachable()` checks the app's CLI socket before the first call: without a running Obsidian, the `obsidian` binary would launch the app and hang instead of answering.
- `e2e/helpers/vault.js` — `checkVaultSafe()` / `guardVault()` (writes only to a vault with the `.e2e-vault` marker, adopting an empty one), `bootstrap()` (builds into the vault's own plugin folder, never the repo-root `main.js`, which the manual test vault loads through a symlink), `reset()` (before each test: closes dialogs, including the settings window, which is a popout window in Obsidian 1.15; deletes every note through `app.vault`; writes the test's notes and `data.json` with the plugin disabled, so writing today's note does not start a rollover), `standardNotes()`, `CHECKLIST_PROFILE`, `day()`.
- `e2e/helpers/rollover.js` — drives a rollover as a user does (`openToday()` via the CLI's `daily`, `runCommand()`) and reads the result: review dialog rows, `setOutcome()`, `clickButton()`, `pressEscape()`, recorded notices (notices don't expire while the window is in the background, so `reset()` clears them and a recorder keeps their text), `horizontalOverflow()` (how far anything is wider than its box or past the window's edge; less than a pixel past the edge counts as 0).
- `e2e/helpers/settings-tab.js` — drives the settings tab and the rule dialog: `openSettings()`, `ruleRows()`, `toggleRule()`, `clickRuleControl()` (by the icon's tooltip), `clickSettingsButton()` (a button in the settings window's topmost dialog, such as Add rule, Save, Cancel), `fillRuleDialog()`, `ruleDialog()`, `setTextSetting()`; for the "page does not jump" checks, `scrollRulesIntoView()`, `settingsScrollTop()` / `settingsMaxScrollTop()`, and `markOutsideRules()` / `markStillThere()` (tags an element outside the Rules group; a full redraw of the tab would replace it). Every query runs in `SETTINGS_DOC` (`app.setting.modalEl.ownerDocument`): the settings window is a popout window with its own document, and the rule dialog opens there too. The popout cannot be narrower than 600 px, so phone-width checks call `setViewportWidth(375)` and then `setMobile(true)`, which shows the settings in the main window with Obsidian's phone layout (in that order: the reload picks the phone layout only when the window is already narrow).
- `e2e/setup.js` — global setup: bootstraps once per run; afterwards turns the narrow viewport and mobile emulation off (only when the app answers on its socket, since any CLI call without a running Obsidian would launch it), fails the run if the repo-root `main.js` or `data.json` changed, and lists the screenshots to review (`e2e/screenshots/`, gitignored).
- `e2e/fixtures/notes/` — the previous-day fixture and today's template. `e2e/fixtures/expected/` — the baseline outputs, generated from `main`'s code with `E2E_UPDATE_EXPECTED=1` and reviewed by hand; never regenerate them to make a failing baseline pass.
- Tests: `e2e/cli.e2e.js`, `e2e/vault.e2e.js` (the helpers themselves), `e2e/guards.e2e.js` (cancelled and refused rollovers change nothing), `e2e/baseline.e2e.js` (output matches `main` with newer features off), `e2e/outcomes.e2e.js` (the four outcomes, undo), `e2e/aging.e2e.js` (stale todos, counter placement), `e2e/layout.e2e.js` (review dialog at phone width), `e2e/rules.e2e.js` (rule defaults, badges and moves in the review, the move badge hiding when the todo won't roll, moves ignoring the template heading; todos from under a plain bullet landing at column 0; Not a todo and No stale count in a real rollover; examples reseeded), `e2e/settings.e2e.js` (the Rules settings group and rule dialog: adding, editing and reordering rules, disabled move buttons at the ends, a hand-edited malformed rule opening as something Save can store, and that the page keeps its scroll position when rules change). The pure helper parts have unit tests in `e2e/helpers/*.test.js`, which run with `pnpm test`.
- How many runs: a normal check runs the suite, or one file, once. A new or changed e2e test that depends on timing (dialogs, notices, waits, two actions racing) gets a flakiness check instead: run its file twice, or three times when the test races two actions on purpose, and every run must pass. One failure means the test is flaky, even if the other runs passed: fix the test, never go with the majority.

**Demos:** `pnpm demo <name>` (`vitest.demo.config.js`, same global setup as the e2e tests) runs `e2e/demos/**/<name>.demo.js`, which drives Obsidian with the e2e helpers while a recorder inside the app captures the window, and builds `e2e/demos/out/<name>.gif`. Each CLI call into the app takes about 0.4 s, so the demo helpers make as few as they can.

- `e2e/helpers/recorder.js` — `resolveTarget()` (the main window, or the settings popout found by giving its document a one-off title: windows are only ever found through the e2e vault's own documents, because one Obsidian app also runs the user's own vaults), `startRecording()` / `stopRecording()` / `isRecording()` (a `capturePage()` loop in the main window, about 10 fps, PNG frames plus `frames.json` in `e2e/demos/out/<name>/frames/`, stops itself after `maxMs`; turns caret blinking and background throttling off while it runs), `OUT_DIR`. While Obsidian is behind other windows it draws no frames, so CSS transitions only run while the recorder captures it.
- `e2e/helpers/pointer.js` — `prepareWindow()` / `restoreWindow()` (the page's size in CSS pixels through DevTools viewport emulation, never by resizing the window: on KDE Wayland the compositor can refuse a resize, and one only lands once a covered window draws a frame; plus the side panels), the fake pointer (`showPointer()`, `moveTo()` which scrolls the element into view, `click()`, `choose()` for a review row's outcome, outlined since the native dropdown can't be captured, `removePointer()`), `highlight(selector, ms)` (fading accent bands over matching elements), `reviewSelect()`, `pause()` (the only fixed wait, for viewers).
- `e2e/helpers/demo.js` — `record(name, options, steps)` (window, pointer, recording, then the GIF; cleans up even when a step fails) and `cleanupDemo()` for `afterEach`.
- `e2e/helpers/frames.js` (pure: merge repeated frames, durations, ffmpeg concat list, size check) and `e2e/helpers/gif.js` (`assemble()`: ffmpeg, then gifsicle when installed), with unit tests that skip without ffmpeg.
- `e2e/demos/readme.demo.js` — the README's `demo.gif`, with its fixtures `demo-previous.md` / `demo-template.md` (only demos use them). Re-record after a UI change it shows; the user watches `e2e/demos/out/readme.gif` before it is copied over `demo.gif`, and it must stay under 2 MB.

Plans write an e2e test where they would have written a manual check in the test vault. Keep a manual step only for judging a screenshot.

When a feature is visual or interactive (dialogs, settings, layout), offer the user a private review clip: a throwaway `e2e/demos/private/<feature>.demo.js`, recorded with `pnpm demo <feature>`, handing over the GIF's absolute path. Never commit these.

## Origins and upstream

Daily Catch-Up is an independent plugin that started as a fork of `git@github.com:lumoe/obsidian-rollover-daily-todos.git` (Rollover Daily Todos, the upstream Obsidian community plugin). Upstream changes can still be adopted selectively. The GitHub repository is `hoshposh/daily-catch-up` (renamed from `hoshposh/obsidian-rollover-daily-todos` on 2026-11-10; GitHub redirects the old URL). It is still a GitHub fork of upstream.

**Branching strategy:**

- `main` — primary branch. Upstream's `master` changes are selectively cherry-picked here.
- `master` — tracks the upstream `master` branch (kept in sync to make cherry-picking straightforward).
- `release/v1.3.0` — upstream's unreleased branch, kept for reference. The options worth having were already adapted (see `docs/upstream-v1.3.0-triage.md`).

When pulling in upstream changes: fetch from upstream into `master`, then cherry-pick individual commits onto `main`. Avoid bulk-merging `master` → `main` to stay in control of what behavioral changes are adopted. Upstream still uses the old plugin id, command ids, command name and console prefix, so adapt those in anything you cherry-pick.
