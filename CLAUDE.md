# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pnpm dev          # watch mode build (dev)
pnpm build        # production build → main.js
pnpm test         # run all tests (vitest)
pnpm test -- --reporter=verbose   # run tests with details
pnpm format       # prettier format
pnpm test:e2e     # end-to-end tests in Obsidian (needs Obsidian open with e2e-vault)
pnpm test:e2e e2e/rules.e2e.js   # one e2e file (`pnpm test:e2e -- <file>` runs them all)
pnpm demo <name>  # record e2e/demos/**/<name>.demo.js as e2e/demos/out/<name>.gif (needs Obsidian open with e2e-vault)
```

Run a single test by name:

```bash
pnpm test -- -t "single todo element"
```

## Architecture

This is Daily Catch-Up (plugin id `daily-catch-up`), an [Obsidian](https://obsidian.md) plugin. Obsidian plugins must ship as a CommonJS bundle at `main.js` (built by rollup from `src/index.js`). The `obsidian` import is external (provided by Obsidian at runtime).

**Core files:**

- `src/index.js` — `RolloverTodosPlugin` class (extends `Plugin`). Handles plugin lifecycle (`onload`), vault event registration (`create` starts the automatic rollover; `rename` runs `followRenamedNote()`, which keeps `inboxNotePath` and `backlogNotePath` pointing at their notes when a note or a folder holding one is renamed or moved, saving once when something changed; Obsidian reports a folder rename for the folder and again for each file inside, which the idempotent `followRename()` handles), commands ("Roll over todos now", "Review and roll over todos…", "Bring back from backlog…" (offered only while `backlogNotePath` is set), "Undo last rollover"), and the top-level `rollover()` orchestration logic. `parseNote(lines)` is `getSections()` with the options every source note is read with. `writeRollover({ file, sources, plans, decisions, backlogPath, templaterGuard, buildNotice, undoKind, insertSettings })` is everything after the review (`insertSettings` is `{ templateHeading, leadingNewLine, skipExistingTodos }` as the caller read them before the review, so a change made while the dialog is open waits for the next run), shared by `rolloverDailyNote()` and `bringBackInto()`: `applySources()`, today's note, the Templater safeguard (only with `templaterGuard`; without it today's note is always snapshotted for undo), the backlog append, each source note through `writeSource()`, the notice from `buildNotice(summary)` and the undo entry (`kind: undoKind`, `"rollover"` or `"bring-back"`).
- `src/get-todos.js` — `TodoParser` class + `getTodos()` / `getTodosAndSkipped()` exports, plus the section helpers `getSections()` (todos grouped by full heading ancestry), `removeEmptiedHeadings()` (drops the headings a deletion emptied, not ones that were already empty), `hasHeading()` and `insertUnderHeading()`. Pure logic on arrays of markdown lines. Uses `Intl.Segmenter` for correct Unicode grapheme cluster handling (emoji, combining characters in checkbox content). A checkbox line carrying the `#rolled` tag (`ROLLED_MARKER`, `hasRolledMarker()`: the marker the Journals plugin's own rollover writes) is never rolled, and neither is anything nested under it, blank lines included. The optional `isIgnored(line, headingPath)` option of `getSections()` (wired to "Not a todo" rules) skips an open todo line the same way. Also home to the shared line helpers `LIST_PREFIX`, `TAG_END`, `headingText()` and `isOpenTodo(line, doneStatusMarkers)` (whether the parser takes one line as an open todo; the test skip-existing and Look back use for nested lines).
- `src/source-action.js` — pure `applySourceAction()` for what happens to a source note after rollover (`none` / `delete` / `mark`), acting on line positions from `getSections()` (`incompleteLineIndices`, `skippedLineIndices`), never on line text; with `keepHeadings` (passed by `writeSource()` from the source, `true` for the inbox) delete only removes the lines and keeps the headings they emptied. Plus settings helpers (`resolveSourceAction`, `inboxSourceAction`, `marksSomewhere` (the previous note's action is mark, or an inbox note is set and its action is mark: used by `effectiveDoneStatusMarkers` and the settings tab), `migrateSourceActionSettings`, `normalizeMarker`, `effectiveDoneStatusMarkers`), `markCancelled()` (the Cancel outcome's checkbox change) and `isCancelAvailable()` (Cancel is offered only when the cancel marker is a done marker).
- `src/insert-sections.js` — pure `insertSections()`: puts each section's todos into today's note under the template heading, or under the headings they had in the previous note when there is none, reusing existing headings and creating missing ones.
- `src/insert-todos.js` — pure `dedupeAgainstExisting()` (skip todos already in today's note), `verifyTodosPresent()` (Templater safeguard) and `dropEmptyTodos()` (with `recordDropped`, a section also carries `droppedLineIndices` / `droppedTodos`, the empty todos dropped from it).
- `src/rolled-count.js` — pure helpers for the inline `[rolled:: n]` counter: `parseRolledCount`, `setRolledCount`, `stripRolledCount`, and `insertField` (also used for `[from:: …]`); plus `stripFromField()` (removes `[from:: …]` fields and the space before them) and `fromNote()` (the link target of `[from:: [[X]]]` or `[from:: [[X|alias]]]`, else `null`). A field goes before the first Obsidian Tasks emoji field (so Tasks still reads its fields from the end of the line), else before a trailing block id, else at the end.
- `src/rollover-items.js` — pure review logic: `toItems()` groups a section's todos into items (a todo plus nested lines; skipped completed children and dropped empty todos indented under the head do not split an item), `isStale()`, `defaultDecisions()`, `needsReview()`, `countOutcomes()`, `applyDecisions()` (turns decisions into sections to insert, backlog items and the line indices to move, cancel and delete), `bumpRolledCounts()`, `skippedLinesToDelete()`, `rebaseSections()` (a todo whose parent line does not go to the same place starts at column 0, its nested lines shifted with it; one nested under a todo that goes there too keeps its indentation), and label/summary helpers for the dialog. A skipped or dropped line belongs to the item holding the nearest line above it that is indented less (walking up through skipped and dropped lines, never past a line the parser did not find), or to no item; delete removes it unless it belongs to a Cancel or Leave item. Outcomes are `"roll"`, `"backlog"`, `"cancel"`, `"leave"`. `applyDecisions()` also returns `chosenLineIndices` (the Roll and Backlog items' lines and the dropped empty todos that belong to them), and `summarizeBringBack()` is the bring-back dialog's summary ("2 to bring back, 1 cancelled, 14 stay").
- `src/rollover-plan.js` — the Obsidian-free decision stage of `rollover()`, shared by `index.js` and `rollover-flow.test.js`: `planDecisions()` (drop empty todos, `toItems()`, default decisions), `applyPlan()` (`applyDecisions()`, `skippedLinesToDelete()`, outcome counts; with `deleteOnlyChosen`, for the backlog, delete only removes the Roll and Backlog items and the dropped and skipped lines that belong to them) and `planInsert()` (dedupe against today's note, `bumpRolledCounts()`, then `rebaseSections()` with the previous note's lines).
- `src/rollover-sources.js` — the Obsidian-free orchestration of a rollover over a list of source notes, on top of `rollover-plan.js`, shared by `index.js` and `rollover-flow.test.js`. A source is `{ key, kind, name, file, content, lines, sections, sourceAction, keepHeadings?, countRollover?, placement?, flatten? }`: `key` prefixes its item ids (`""` for the previous daily note, so its ids stay `"0:0"` etc.; any other key must end in a non-digit separator such as `"inbox/"`, and `planSources()` throws on a duplicate id), `kind` is what the source is (`"previous"`, `"earlier"`, `"inbox"`, or `"backlog"` for Bring back from backlog), `name` is the note's basename (dialog title and "From …" rows, "left in …", `[from:: [[…]]]`), `sourceAction` is `resolveSourceAction()` for the previous note; `keepHeadings` makes delete keep the headings it empties, `countRollover: false` keeps every item's `[rolled:: n]` as it is, and a `placement` heading becomes each item's `moveTo` unless a Move to heading rule set one; `flatten` inserts its rolled sections without their headings (moved ones keep their target); a missing field means the previous note's behaviour. `inboxSource({ file, content, lines, sections, settings })` builds the inbox's source: `{ key: "inbox/", kind: "inbox", name: file.basename, …, sourceAction: inboxSourceAction(settings), keepHeadings: true, countRollover: false, placement: normalizeHeading(inboxHeading) or null }`, where `inboxSourceAction()` (defined in `source-action.js`, re-exported here) is `"mark"` for `"mark"` and `"delete"` for anything else (never `"none"`, or the inbox would be pulled every day). `earlierSource({ file, content, lines, sections, settings, newerDoneKeys })` builds an older daily note's source for Look back: `{ key: file.path + "/", kind: "earlier", name: file.basename, …, sourceAction: resolveSourceAction(settings), newerDoneKeys }` (the path, not the basename, is the key, since a format with folders can give two notes one basename; no `keepHeadings`, `countRollover` or `placement`, so it behaves as the previous note does), and `earlierSources({ todayLines, previousLines, notes, settings, doneStatusMarkers })` builds one per older note (`notes` newest first, each `{ file, content, lines, sections }`, `doneStatusMarkers` from `lookBackDoneMarkers()`): it owns the "done in a newer note" key layout, `cumulativeDoneKeys()` over today's note, the previous note and the older notes, so each source's `newerDoneKeys` are the keys done in every note newer than it; `index.js` and `rollover-flow.test.js` both call it. `inboxPathConflicts({ inboxPath, todayPath, previousPath, backlogPath, earlierPaths })` is the inbox guard (a null path is not compared; `earlierPaths` are the older notes read) and `INBOX_GUARD_NOTICE` its text, `inboxGuardNotice({ inboxPath, earlierPaths })` picks the text (a variant naming "a daily note the rollover reads" when the inbox is one of the older notes), and `backlogPathConflict({ backlogPath, todayPath, previousPath, earlierPaths })` is the backlog guard: the notice to show, or `null` (`BACKLOG_GUARD_NOTICE` for today's or the previous note, `BACKLOG_GUARD_EARLIER_NOTICE` for an older one). `planSources()` runs `planDecisions()` per source and joins the items and default decisions; for an `"earlier"` source only, items whose `item.rule.outcome` is `"leave"` get `hidden: true` and stay Leave, even when done in a newer note (a rule's Leave is checked first), and its other items done in a newer note (`handledItemIds()`) get `handled: true, hidden: true` with the decision `"roll"`, whatever a rule's Backlog or Cancel says (so its source action marks or deletes them); the planning `settings.doneStatusMarkers` are `lookBackDoneMarkers()`; it also returns `reviewItems`, the items without `hidden`, which the dialog, `needsReview()` and the "items to show" check use instead of `items`; `applySources()` runs `applyPlan()` per source (`perSource`, which also holds `handledLineIndices`, `handledCount` and `leftCount`, the items decided Leave that were not hidden), tags each backlog item with its source's `sourceName` and adds up the outcome counts; `insertSources()`, called inside today's `vault.process()`, runs `planInsert()` and `insertSections()` per source against the content the earlier sources left (skipping `insertSections()` when nothing is left, so the note stays byte for byte) and returns per source `todosAlreadyPresent`, `duplicateTodos`, `retainedLineIndices`, `insertedTodos` and `todosDoneElsewhere` (the handled lines kept out of today's note: `planInsert()` takes `handledLineIndices` from `applySources()` and also puts those lines in `retainedLineIndices`, so mark with `moveNested` leaves their nested lines), plus `templateHeadingNotFound`; `sourceNeedsWrite(source, decided)` says whether a source note goes through `vault.process()` at all: a source whose action is `"none"` only for Cancel marks, an `"earlier"` one only when it has moved, cancelled, deleted or skipped-to-delete lines (one holding only Leave items, a rule's or the user's, is not opened), the previous note and the inbox otherwise always; `writeSource({ content, source, decided, retainedLineIndices, settings }) → { content, changed }` is what one source note becomes, called inside its `vault.process()` once the "edited meanwhile" check passed: `markCancelled()` (cancel marker, effective done markers), then, unless `sourceAction` is `"none"`, `applySourceAction()` (source marker, the raw `doneStatusMarkers`, `moveNested` = `moveNestedItemsOnMark && rolloverChildren`, `retainLineIndices`), with `settings` the plugin settings; `rolloverNotice()` builds the notice text from the counts (per source `kind` and `rolledCount`: when more than one source contributed, the rolled line names each non-previous source that did, the older notes summed into one part, "(3 from earlier notes, 2 from Inbox)" ("1 from an earlier note" for one); `doneElsewhereCount` adds "- 2 already done in a newer note."; one empty-todo line summed over the sources that delete; one "left in {name}" line per source). The other notices name the sources through `sourceLabel()` ("the previous day's note", "the daily note '{name}'" for an older note, "the inbox note '{name}'"): `sourceUnchangedNotice(source)` (edited meanwhile), `templaterNotice(sources)` (`templaterNoticeSources(sources, perSource)` picks the sources it names: every one but an older daily note with nothing to write), `backlogFailedNotice({ backlogPath, error, todosAdded, sources })` and `sourceWriteFailedNotice(source, error)`; with the previous note as the only source they return the texts the plugin always showed. The sources are the previous daily note, the older daily notes Look back reads (newest first) and, when set, the inbox note. `backlogSource({ file, content, lines, sections })` is the source of Bring back from backlog, alone: `{ key: "backlog/", kind: "backlog", name: file.basename, …, sourceAction: "delete", keepHeadings: true, countRollover: false, flatten: true }`. For it `planSources()` decides every item `"leave"` and drops each item's rule `outcome` / `outcomeRule` (Move to heading still applies); `applySources()` passes `deleteOnlyChosen` (empty and completed todos that belong to no chosen item stay), strips `[from:: …]` from each rolled head (`stripFromField()`) and, with `flatten`, gives every rolled section without `moveTo` an empty `headingPath`; `sourceNeedsWrite()` treats it as an `"earlier"` source; `sourceLabel()` is "the backlog note '{name}'", and `sourceUnchangedNotice()` / `sourceWriteFailedNotice()` start with "Bring back"; both take `{ moved }` (whether any of the note's todos went to today's note or the backlog, for every kind) and without it leave out the sentence saying its todos were added to today's note. A backlog item without a decision is read as `"leave"` by `applySources()`, so nothing leaves the backlog unless chosen. `bringBackNotice({ broughtBack, alreadyPresent, cancelled, name, templateHeadingNotFound, templateHeading })` is its notice.
- `src/look-back.js` — pure logic for Look back (reading the daily notes of the last N days; never imports `moment` or reads `window`: days are local `"YYYY-MM-DD"` strings and `today` is passed in). `lookBackDependenciesMet(settings)` (`resolveSourceAction()` is `"mark"` or `"delete"`, the inbox's action not counting, and `skipExistingTodos` is on) and `lookBackApplies(settings)` (those and `lookBackDays` a whole number above 0) are the one decision, used by `dependentSettingStates()`, the settings tab and `rolloverDailyNote()`; `lookBackDoneMarkers(settings)` (`effectiveDoneStatusMarkers()`, or `"xX-"` when that is empty, as the parser falls back: the done markers of "done in a newer note", which `index.js` and the flow test pass to `earlierSources()` and `planSources()`); `isValidDay()`; `nextLookBackSince({ wasApplying, previousDoneMarkers, settings, today, remembered })` (the stored start day after a settings change: today when Look back has just started applying, `""` when it has stopped, today too when it keeps applying but `previousDoneMarkers` (the `lookBackDoneMarkers()` before the change) has a character the new ones lack: Mark to Delete, a new Marker character, a character taken out of Done status markers, since the lines marked or finished with it would read as open again; while it applies, `remembered` (`{ since, doneMarkers }`, the day Read notes from last held in the same settings session) wins whenever all its done markers count, so a setting turned off and on again within one session brings the day back; else as stored); `settledLookBackSince(settings, today)` (`{ since, changed }`: today when Look back applies but the stored day is empty or invalid, which `rolloverDailyNote()` then saves); `parseLookBackDays(text)` (whole number 0 to 366, else `undefined`) and `parseLookBackSince(text, today)` (empty is today, a valid day not after today is kept, else `undefined`). "Done in a newer note": `todoKey(line)` (a checkbox line's text after the checkbox without its `[rolled:: n]` counter and without an Obsidian Tasks done `✅ YYYY-MM-DD` or cancelled `❌ YYYY-MM-DD` date, runs of whitespace made one, trimmed, so a todo and its copy match whatever the indentation, quote prefix, list marker or completion date), `checkboxMarker()` (both used only to match a todo with its done copy, and stricter than the parser on purpose: a list marker (`-`, `*`, `+` or a number), `[`, one grapheme that is not a zero-width or direction character, `]`, then a space or the end of the line; anything else, such as `- [[Sam Smith]] note`, `- [[]] x` or `- [ ]sub`, gives `null`, so an odd line never counts as a done copy. The parser itself takes `-`/`*`/`+` with one space before `[` and needs nothing after `]`, so it rolls `- [ ]sub` and `- [[]] x` as todos), `doneKeys(lines, doneStatusMarkers)` (the keys of the checkbox lines with a done marker), `cumulativeDoneKeys(linesList, doneStatusMarkers)` (for notes newest first, entry k holds the done keys of the notes newer than note k) and `handledItemIds(items, newerDoneKeys, doneStatusMarkers)` (the ids of items whose head is done in a newer note and whose nested open todos all are; a nested line is open work by the parser's own `isOpenTodo()`, as for skip-existing, so whatever the parser would roll blocks, and plain bullets, links and completed children never do).
- `src/rules.js` — pure rule logic: `EXAMPLE_RULES` (nine, all switched off), `ruleProblem()` (why a rule can't be used), `ruleMatches()`, `isIgnoredByRules()` (for the parser), `ruleResult()` (an item's `outcome`, `noStale` and `moveTo`, each with the rule that set it: first match per kind wins, kinds combine, an unavailable outcome falls back without the next rule taking over), and the settings-facing `ruleLabel()`, `ruleSummary()`, `ruleNote()`, `ruleDraft()` (a hand-edited rule coerced into what the rule dialog can show and save), `newRuleId()`, `MATCH_LABELS`, `EFFECT_LABELS`.
- `src/backlog.js` — pure `appendToBacklog()` / `backlogLines()`: adds parked items to the backlog note's content under a heading (created when missing) or at the end, with the counter stripped and `[from:: [[source note]]]` added.
- `src/note-paths.js` — pure `followRename(notePath, oldPath, newPath)`: where a setting's note path ends up when the note or a folder containing it is renamed or moved (`null` when untouched, or when `notePath` is null, so a repeated event for the same rename changes nothing).
- `src/daily-notes.js` — the only code that reads the daily-notes settings or decides which files are daily notes (it replaced `obsidian-daily-notes-interface`), with `moment` and `app` passed in so all of it is unit tested. Pure: `cleanFolder()`, `noteDate(path, { folder, format }, moment)` (a note's date when its path inside the folder, minus `.md`, parses strictly with the full format; `null` otherwise, so a note in a subfolder the format doesn't describe is not a daily note), `todayNotePath()`, `dailyNotes()` (`[{ file, date }]`, newest first), `previousDailyNote()` (the newest daily note dated before today) and `notesInWindow(files, settings, today, moment, { count, period, since })` (`[{ file, date }]` newest first: the dated notes from `count` periods back, `period` being `"day"`, `"week"` or `"month"`, up to but not including the start of today's period; a `since` moment cuts the window short at the start of that day; `[]` for a count that is not above 0; only `"day"` is used so far). Settings: `getDailyNoteSettings(app)` (`{ folder, format, template }` from Periodic Notes' `daily` when it is enabled, else from core Daily Notes; folder cleaned; `null` when unreadable) and `isDailyNotesEnabled(app)`.
- `src/template-headings.js` — pure helpers for the template heading setting (`extractHeadings`, `headingOptions`).
- `src/settings-dependencies.js` — pure `dependentSettingStates()`: for each dependent setting (`DEPENDENT_SETTINGS`), whether it applies and, if not, the reason shown in place of its description (`lookBackDays` needs `lookBackDependenciesMet()`, `lookBackSince` needs `lookBackApplies()`, each with a reason naming what to change); plus `cancelMarkerNote()`.
- `src/settings-text.js` — the settings tab's text: `SETTING_GROUPS` (eight groups with their `?` help, `**bold**` markup split by `helpSegments()`), `SETTING_LABELS` and the one-line `SETTING_DESCRIPTIONS` (capped at 160 characters by `settings-text.test.js`, so the "safe if After rollover was already Mark or Delete back then" advice for Read notes from lives in the Which todos roll over group's help, next to the Look back paragraph). Look back (days) and Read notes from sit in that group, under Skip todos already in today's note.
- `src/ui/RolloverSettingTab.js` — Obsidian `PluginSettingTab` for the settings panel: renders the eight groups from `settings-text.js`, with dependent settings indented under their parent and a `?` help panel per group. After every change `refreshDependents()` greys out the settings that don't apply (from `settings-dependencies.js`) in place, so the page never re-renders or jumps. After every change `save()` also runs `settleLookBackSince()` (`nextLookBackSince()`, given whether Look back applied and its `lookBackDoneMarkers()` before the change, both kept by `rememberLookBack()`), which sets or clears Read notes from and updates its field in place; editing that field is not such a change. The tab also keeps `lookBackRemembered` for the current session (`rememberSince()`: set at render and when a day is typed into the field, detected through `lookBackSinceKnown`; cleared at every render) and passes it as `remembered`. The Rules group (`renderRules()`) rebuilds only itself, and builds the new rows off the page before swapping them in: emptying it first made the page jump when a rule was moved.
- `src/undo-merge.js` — pure `restoreKeepingNewLines({ before, after, current })` (a three-way line merge by LCS: `before` with each run of lines `current` gained over `after` put just before the `before` line matched to the next matched `after` line, or at the end; `current === after` gives `before`; an edited line comes back as the original plus the edit) and `addedLineCount({ after, current })`; used for the inbox's undo entry.
- `src/ui/UndoModal.js` — Obsidian `Modal` for the undo confirmation dialog: restores today's note and each source note in the undo entry's `sources` list (each listed by file name; an entry with `keepNewLines`, the inbox's, is restored through `restoreKeepingNewLines()` and its line says how many added lines are kept, when any), and restores or deletes the backlog note; its description names the inbox note only when one is set, and an entry with `kind: "bring-back"` gets its own description, and "Today's note will not be changed." when it added nothing to today's note (Cancel only). Restores notes with `vault.process()`.
- `src/ui/ReviewModal.js` — Obsidian `Modal` for the review dialog, taking `sources: [{ name, sections, items }]` (a source without items is not shown; with one source it is titled `Roll over from {name}`; with more it is titled `Roll over todos` and each source starts with a heading row `From {name}` (class `rollover-review-source`) with its own All roll / All leave, followed by its sections; the top "All todos" row covers every source): one dropdown per item, section and global shortcuts, a live summary (counting only the items it was given, since the decision map also holds an older note's hidden ones), and badges naming the rule behind an item's default and its move target. `index.js` passes only the shown items, so an older note's hidden ones (done in a newer note, or left by a rule) are neither listed nor touched by the All buttons; each older note with shown items starts with its own `From {name}` row. `openAndWait()` resolves with the decisions on Apply and `null` otherwise. With `mode: "bringBack"` it is the backlog's dialog: titled `Bring back from {name}`, outcomes labelled Bring back / Stay / Cancel (keys `roll` / `leave` / `cancel`), shortcuts All back / All stay, summary from `summarizeBringBack()`, labels without `[from:: …]` and a `from {note}` badge (`rollover-from-badge`), no stale badge. UI only; logic lives in `rollover-items.js`.
- `src/ui/RuleModal.js` — Obsidian `Modal` for adding or editing one rule (match, value, effect, target heading), validated live with `ruleProblem()`. `openAndWait()` resolves with the rule on Save and `null` otherwise. The settings tab's Rules group (rows with switch, summary, `ruleNote()`, edit / up / down / delete, then Add rule) re-renders only its own container.
- `styles.css` — styles for the review dialog and the settings tab's indented dependents and help panels (theme CSS variables only, wraps at phone width). Shipped with the release next to `main.js` and `manifest.json`.

**Plugin settings** (defaults in `loadSettings`):

- `templateHeading` — heading to insert todos under (or `"none"` for end of file)
- `onRolloverSourceAction` — `"none"` (default), `"delete"` or `"mark"`: what to do with rolled todos on the previous day's note (replaces the old `deleteOnComplete` boolean, which is migrated to `"delete"`)
- `rolloverSourceMarker` — checkbox character used by `"mark"` (default `">"`); counts as a done marker while marking (in the previous note or the inbox: `marksSomewhere()`), without changing `doneStatusMarkers`
- `moveNestedItemsOnMark` — with `rolloverChildren`, for every note set to `"mark"` (the previous day's note and the inbox), keep only the marked todo in its note and remove the rolled items nested under it (they moved to today's note); completed children stay when `skipCompletedChildren` is on
- `skipExistingTodos` — don't roll over todos (with their children) that today's note already has; also a requirement of Look back
- `ignoreBlockquotes` — don't roll over todos inside blockquotes/callouts
- `skipCompletedChildren` — with `rolloverChildren`, leave completed child todos out (removed with their parent when deleting)
- `removeEmptyTodos` — skip empty `- [ ]` items
- `rolloverChildren` — include indented child items under a todo
- `rolloverOnFileCreate` — auto-trigger on vault `create` event
- `doneStatusMarkers` — string of characters treated as "done" (default `"xX-"`)
- `reviewOnAutoRollover` — `"off"` (default), `"stale"` or `"always"`: whether an automatic rollover opens the review dialog (the "Review and roll over todos…" command always does)
- `cancelMarker` — checkbox character for the Cancel outcome (default `"-"`); Cancel is offered only when it is one of the done markers (`isCancelAvailable`), and `effectiveDoneStatusMarkers` is not changed for it
- `trackRolloverCount` — default `false`: write `[rolled:: n]` on each rolled todo, raised by 1 per rollover
- `staleAfterRollovers` — default `5`: a todo is stale once its count is at least this (0 disables); only used with `trackRolloverCount`
- `staleBehavior` — `"keep"` (default) or `"backlog"`: default outcome of stale todos, and what happens to them when no review is shown (needs a backlog note)
- `backlogNotePath` — default `""`: note that receives Backlog items; empty disables the Backlog outcome. Cannot be today's or the previous note, or an older daily note Look back reads
- `backlogHeading` — default `""`: heading in the backlog note to add items under (empty = end of note); text that does not match `/^#{1,6}\s/` gets a `## ` prefix
- `inboxNotePath` — default `""`: the inbox note whose open todos every rollover pulls in (`.md` added when missing, like the backlog note); empty turns the inbox off. Cannot be today's note, the previous daily note, an older daily note Look back reads or the backlog note
- `inboxSourceAction` — `"delete"` (default) or `"mark"`: what happens to pulled todos in the inbox (no `"none"`; any other stored value counts as `"delete"`). Mark uses `rolloverSourceMarker` and `moveNestedItemsOnMark`, like the previous note; delete keeps the inbox's headings and the note itself
- `inboxHeading` — default `""`: heading in today's note for inbox todos, used like a Move to heading target (`normalizeHeading()`); empty puts them where rolled todos go
- `rules` — ordered list of `{ id, enabled, match: "tag"|"heading"|"regex", value, effect: "roll"|"backlog"|"cancel"|"leave"|"ignore"|"noStale"|"move", target? }`. Seeded with `EXAMPLE_RULES` (all off) when the stored settings have no `rules` key, never reseeded
- `lookBackDays` — default `0`: with Look back applying (`lookBackApplies()`), also read every daily note dated within this many days before today, besides the previous one; a whole number from 0 to 366 (anything else is not saved), and 0 or missing means off. A dependent setting: only available with `onRolloverSourceAction` `"mark"` or `"delete"` and `skipExistingTodos` on; a disabled one keeps its value, and `rolloverDailyNote()` checks the same dependencies, so nothing older is read while they are not met
- `lookBackSince` — default `""`: `"YYYY-MM-DD"` local date (shown as Read notes from); an older note dated before it is never read (the previous note always is). The settings tab sets it to today whenever a change makes Look back go from not applying to applying, or loses a done marker while it applies (Mark to Delete, a new Marker character, a Done status marker removed), and clears it when it stops applying, a chosen date included (`nextLookBackSince()`); editing the field is not such a change; within one settings session a reset day comes back once the change is undone (`remembered`, kept by the tab, cleared each time it renders); the field takes an earlier date, an empty one means today and a later one is not saved. At run time an empty or invalid value, with Look back applying, is set to today and saved, and no older notes are read on that run
- `leadingNewLine` — blank line between a heading and the first todos inserted under it, and before a heading the rollover adds; todos added to an existing list continue it without one

**Rollover flow:** On daily note creation (or a command), `rollover()` validates the file is today's daily note (created within 5 seconds); while another rollover is still running (`rolloverInProgress`, e.g. its dialog is open) an automatic run returns silently and a command shows a notice. `rolloverDailyNote()` then finds the previous daily note via `getLastDailyNote(today)` (`previousDailyNote()`: the newest daily note dated before today, with the time `rollover()` read once), the older daily notes when Look back applies (below) and the inbox note (`getInboxPath()`, `null` when `inboxNotePath` is empty), groups each one's unfinished todos by heading with `getSections()` (same options for all), and builds the list of sources from them: the previous note, the older notes newest first, then the inbox (`rollover-sources.js`; a note without open todos is dropped, and an empty list ends the rollover silently). With no previous daily note the rollover ends at once unless an inbox is set; with one set, a missing previous note or one without open todos does not stop the inbox's todos. While the sources are built, the inbox guard (`inboxPathConflicts()`: the inbox is today's note, `lastDailyNote?.path` or the backlog note when one is set) stops the rollover with `INBOX_GUARD_NOTICE` before the backlog guard runs, so an inbox that is also the backlog note gets this notice and not the backlog one; a missing inbox note is skipped without a notice. After planning, the backlog guard (`backlogPathConflict()`) compares the backlog note with today's note and `lastDailyNote` itself (whether or not it is a source; skipped when there is none). Both guards also stop when the note is one of the older notes being read (`earlierPaths`), with their own notice texts. **Look back:** when `lookBackApplies(settings)`, `settledLookBackSince()` settles the start day (saving it when it was empty or invalid), `notesInWindow()` lists the daily notes dated within the last `lookBackDays` days before today and not before that start day, the previous note left out, they are read and parsed like the previous note, today's note is read once before the review for the done keys (the write still reads it again inside `vault.process()`), and `earlierSources()` builds their sources, placed between the previous note and the inbox; a note without open todos is dropped, and the early return with no previous note and no inbox stays. Items of an older note that are done in a newer note (`kind: "earlier"` only) are handled: hidden from the review, never inserted into today's note, but marked or deleted by the source action, so `rolloverNotice()` counts them separately. Rule-chosen Leaves of older notes are hidden from the review too and never counted in the notice's "left in" lines or by `needsReview()`; they stay as they are, even when done in a newer note (checked before handled). "Done" uses `lookBackDoneMarkers()`, so an empty Done status markers field means `xX-`, and `todoKey()` ignores an Obsidian Tasks done or cancelled date. A hand-chosen Leave means "not today": the item stays open, and the next rollover reads that note again while it is inside the window. The review dialog is given only the shown items, and the decisions it returns still hold the hidden ones. Each source is planned on its own (`planSources()`), the dialog and `needsReview()` see all `reviewItems` together, the decisions are applied per source (`applySources()`), today's note gets each source's todos in turn (`insertSources()`), and each source note is written in its own `vault.process()` in list order. Review stage (`planDecisions()`, per source): empty todos are dropped with `removeEmptyTodos`, `toItems()` groups the todos into items, each gets its `ruleResult()` as `item.rule`, `defaultDecisions()` picks an outcome per item (a rule's outcome first; otherwise Roll, except stale items under `staleBehavior: "backlog"` when a backlog note is set; `isStale()` is false for No stale count items), and `ReviewModal` lets the user change them when the "Review and roll over todos…" command was used or `needsReview()` says so for an automatic run. It only opens when there are `reviewItems`, and closing it abandons the rollover with nothing written. `applyPlan()` (`applyDecisions()`) turns the decisions into the sections to insert (Roll items only), the items for the backlog, and the line positions to cancel, delete or leave. Today's note is read after the review, in the same `vault.process()` that writes it, so planning and writing see the same content. Roll items a Move to heading rule sends elsewhere leave their section for a moved section (`moveTo`), which `insertSections()` puts under the first heading with that text anywhere in today's note, or under a new one at the end, ignoring the template heading. The Roll sections are inserted with `insertSections()` (under the template heading, or under their own recreated headings when there is none), optionally skipping todos today's note already has, with `[rolled:: n]` raised by `bumpRolledCounts()` when `trackRolloverCount` is on, except for No stale count items (`noStaleLineIndices`), and with each todo whose parent stays behind or goes elsewhere re-based to column 0 (`rebaseSections()`) (all in `planInsert()`). "Not a todo" lines never get this far: the parser skips them. Backlog items are then appended with `appendToBacklog()` (the note and its folder are created when missing; if the write fails every source note is left untouched, with `backlogFailedNotice()`). Last, each source note (the previous day's note, the older notes, then the inbox) that `sourceNeedsWrite()` says has something to change changes in its own `vault.process()`, with its own "edited meanwhile" check, through `writeSource()`: Cancel items are marked first with `markCancelled()` (never deleted), then the configured source action (`delete` / `mark`) runs on Roll and Backlog items only. Both use the line positions of the note as it was parsed, which stay valid because marking only rewrites checkboxes. Leave items are untouched. A source edited meanwhile is left unchanged with `sourceUnchangedNotice()`. A source whose `vault.process()` throws is logged (`console.error`), gets `sourceWriteFailedNotice()`, no undo entry and no cancelled count, and the loop goes on with the next source; the loop and the final notice sit in a `try` whose `finally` records the undo entry, so whatever was written stays undoable. If Templater is enabled and a source's action is destructive, it first waits 3 seconds and checks that the inserted todos survived (else `templaterNotice(templaterNoticeSources(sources, perSource))`, which leaves out older notes with nothing to write, and no source is touched). The notice text comes from `rolloverNotice()`. Undo history (`{ today, backlog, sources: [{ file, oldContent }] }`, `sources` holding each source note the rollover changed; the inbox's entry also has `newContent`, the inbox as the rollover wrote it, and `keepNewLines: true`, so undo keeps lines added to it since) is kept for 2 minutes and also snapshots the backlog note (undo deletes it when the rollover created it); with Templater enabled only the source notes (previous day's note, older notes, inbox) and the backlog note are snapshotted. Each older note the rollover changed is in `sources` like the previous note, restored whole.

**Bring back flow:** "Bring back from backlog…" runs `bringBack()`: daily notes settings and today's note (a notice when it doesn't exist; it is never created), the same `rolloverInProgress` lock as `rollover()`, then `bringBackInto()`: the backlog guard (the backlog note is today's note: `BACKLOG_GUARD_NOTICE`), a notice for a missing backlog or one without open todos, `planSources()` on `[backlogSource(…)]` with `backlogEnabled: false`, and `ReviewModal` with `mode: "bringBack"`, always shown. Closing it changes nothing; Apply with no item on Bring back or Cancel shows "Nothing brought back." and writes nothing (the previous undo entry stays). Otherwise `writeRollover()` with `templaterGuard: false` (today's note is not new) and `undoKind: "bring-back"`: the chosen todos go into today's note like rolled ones, the backlog note is written with its own "edited meanwhile" check, and undo restores both.

## Origins and upstream

Daily Catch-Up is an independent plugin that started as a fork of `git@github.com:lumoe/obsidian-rollover-daily-todos.git` (Rollover Daily Todos, the upstream Obsidian community plugin). Upstream changes can still be adopted selectively. The GitHub repository is `hoshposh/daily-catch-up` (renamed from `hoshposh/obsidian-rollover-daily-todos` on 2026-11-10; GitHub redirects the old URL). It is still a GitHub fork of upstream.

**Branching strategy:**

- `main` — primary branch. Upstream's `master` changes are selectively cherry-picked here.
- `master` — tracks the upstream `master` branch (kept in sync to make cherry-picking straightforward).
- `release/v1.3.0` — upstream's unreleased branch, kept for reference. The options worth having were already adapted (see `docs/upstream-v1.3.0-triage.md`).

When pulling in upstream changes: fetch from upstream into `master`, then cherry-pick individual commits onto `main`. Avoid bulk-merging `master` → `main` to stay in control of what behavioral changes are adopted. Upstream still uses the old plugin id, command ids, command name and console prefix, so adapt those in anything you cherry-pick.
